# 브이로그형 릴스

내레이션 한 트랙 + 소리 끈 촬영 영상 + 구절 자막 + (선택) 헤드카피를 서로 독립한 레이어로 쌓는다. 자막이 바뀔 때마다 영상이나 제목이 같이 바뀌지 않는다.

## 준비
공통 준비(ffmpeg, Node 22, HyperFrames, 받아쓰기, 글꼴)는 `reels-style-router/SKILL.md`의 "공통 준비"를 따른다. 필요한 입력과 계획 파일 항목은 `references/implementation.md`, 자막·헤드카피·출력 기본값은 `references/production-profile.json`이다.
- 재료: 학생이 찍은 여러 촬영 클립, 말 사이를 정리한 내레이션 음성(없으면 `video-studio`의 편집 절차로 정리해 학생 확인), 실제 발화를 받아쓴 구절 자막.
- 카카오톡 등 대화방에서 받은 영상은 원본 파일 이름과 해시를 기록한다. 받은 권한은 그 사람에게 메시지를 보낼 권한이 아니다.

## 편집 기준
- 시간축은 정리된 음성 마스터다. 스타일을 고치는 동안 무음 삭제·다시 자르기·배속을 다시 하지 않는다.
- 단어 시간과 실제 말로 짧은 구절 자막을 만든다. 자막 수, 음성 연결 지점 수, 영상 컷 수는 서로 달라도 된다. 영어 영상의 속도 기준을 한국어에 그대로 적용하지 않는다.
- 영상 전환은 문장의 뜻과 리듬으로 잡는다. 짧은 도입 뒤 보통 1~3초, 필요한 장면은 더 길게. 컷 수와 길이를 고정하지 않는다.
- 한 촬영 파일의 서로 다른 구간을 여러 컷에 써도 된다. 필요한 최종 컷 수와 필요한 원본 파일 수를 따로 보고한다. 실제 내용과 맞지 않는 장면을 사실 증거처럼 쓰지 않는다.
- 헤드카피는 학생이 정한 문구를 쓴다. AI가 제안한 문구를 학생이 확정한 것처럼 기록하지 않는다. 새 문구가 필요하면 학생과 함께 정한다.

## 화면과 출력
- 말 자막: 위에서 약 45% 지점, 흰색 한 줄, 진한 검정 그림자(배경 상자 없음). 헤드카피: 첫 1초, 두 줄 같은 크기의 굵은 흰 글자, 검정 외곽선. 기본값은 `references/production-profile.json`이고 학생 요청이나 계획 파일 값이 우선한다.
- 기본 출력은 세로 4K 2160x3840, 30fps. 1080x1920 기준으로 설계하고 렌더 단계에서 4K 비율을 유지한다. 낮은 해상도 촬영본이 4K 세부로 복원됐다고 말하지 않는다.

## 순서 (AI가 실행)
1. 재료와 학생 확인(자막 문구, 헤드카피)을 받는다.
2. `edit-plan.json`을 만든다(`references/implementation.md`의 필수 입력). 글꼴과 GSAP 파일은 `reel-reference-edit`의 동봉 글꼴과 고정 버전 확인 도구를 쓴다.
3. `scripts/build_composition.py`가 계획의 시간과 미디어 길이를 검사하고 HTML을 만든다. 이 스크립트는 받아쓰기, 음성 편집, 문구 생성은 하지 않는다.
4. `scripts/render.py`가 전체 검사 -> 4K 렌더 -> 해상도·fps 검증을 한다. 이미 렌더를 허락받았으면 중간에 같은 허락을 또 묻지 않는다.
5. 검수: 실제 해상도·fps·길이·음성 확인, 컷별 대표 화면과 움직임, 자막 글자 잘림, 헤드카피 두 줄 크기와 등장·퇴장 시점. 직접 들어 보지 않았으면 "청취 미확인"으로 적는다.
6. 수정은 계획 파일과 생성기를 고쳐 새 버전으로 다시 렌더한다(MP4나 HTML을 직접 고치지 않는다). 최종 MP4 위치와 검수 결과를 학생에게 알린다. 올리는 일은 하지 않는다.
