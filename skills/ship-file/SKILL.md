# 출고·배송 관리 담당자 — ship-file

## 하는 일
주문을 읽어 보류 조건(필수 칸 비어 있음)을 먼저 걸러내고, 같은 집은 합치고, 포장 규칙으로 박스 수를 정하고, 우편번호 범위로 도서산간을 표시해 택배사 업로드 파일·보류 목록·출고 준비 화면을 만든다.
결과는 AI가 느낌으로 매기는 것이 아니라 스크립트가 표(규칙)대로 세고 판정한다. 기준을 바꾸고 싶으면 스크립트가 아니라 규칙 표를 고친다.

## 필요한 것
- 필요한 프로그램: Python 3 (없으면 멈추고 무엇이 없는지 한 줄로 알린다)
- 키·로그인: 없음. 이 스킬은 아무 서비스에도 접속하지 않고 파일만 읽고 쓴다.

## 작업 폴더
- 작업 폴더는 지금 작업 폴더 안의 `출고-파일` 로 한다. 처음 실행하면 연습 자료와 규칙 표가 그 안에 한 번만 복사된다. 이미 있는 파일은 덮어쓰지 않는다.
- 스킬 폴더의 `samples` 는 원본이다. 고치지 않는다. 사용자가 고치는 것은 작업 폴더의 복사본이다.

## 순서
1. 먼저 한 가지를 묻는다: "연습 자료로 먼저 한 번 볼까요, 바로 내 자료로 할까요?" 연습 결과를 사용자의 실제 결과처럼 말하지 않는다.
2. 내 자료로 할 때: 주문은 `01_주문/주문_샘플.csv` 형식의 CSV. 칸: 주문번호, 받는 사람, 전화, 우편번호, 주소, 상품, 수량, 배송메모. 내 파일로 하려면 `--orders <파일>`.
   내 자료의 칸 이름이 다르면 사용자에게 어느 칸이 무엇인지 한 번 확인하고, 원본은 고치지 않고 칸 이름을 맞춘 사본을 쓴다.
3. 규칙 표를 내 것으로 바꾼다. 무엇으로 바꿀지 모르면 사용자에게 묻는다(지어내지 않는다).
   - `02_규칙/포장규칙.csv` (상품, 박스, 한 박스 최대 개수): 내 상품·박스·개수
   - `02_규칙/도서산간.csv` (우편번호 시작, 우편번호 끝, 지역, 추가 배송비): 택배사 기준 도서산간 우편번호 범위(최신 기준은 택배사 안내로 확인)
   - `02_규칙/보류조건.csv` (비어 있으면 보류할 칸, 이유)
4. 이 스킬 폴더의 `scripts/run.py` 를 Python 으로 실행한다. 작업 폴더는 `--work <작업 폴더 경로>` 로 넘긴다 (선택 옵션: 송장 파일 변환: `--invoice <택배사 송장 파일>`(쇼핑몰 일괄 등록용 파일을 만들 뿐 올리지 않는다)). 이 줄은 AI용이다. 사용자에게 명령어를 보여 주지 않는다.
5. 결과를 열어 본다. 만들어지는 것: 결과/택배사_업로드.csv, 결과/보류목록.csv, 결과/쇼핑몰_송장등록.csv, 결과/출고준비.html. HTML 화면은 허브 오른쪽 미리보기에 띄운다.
6. 스크립트가 알려 주는 확인 3가지를 읽고 그대로 전한다.
   - 업로드 파일에 주소·전화 빠진 줄이 없나
   - 합칠 수 있는 주문을 합쳤나
   - 도서산간 표시가 빠지지 않았나
   "확인 필요"가 있으면 이유를 쉬운 말로 알리고, 규칙 표를 어떻게 고치면 되는지 제안한 뒤 다시 돌린다. 표를 고치기 전에 사용자에게 먼저 묻는다.
7. 사람 눈으로 한 번 더 볼 것을 사용자에게 알린다(`references/검수표.md` 참고).
   - 택배사 업로드 양식의 칸 순서·이름이 내가 쓰는 택배사 양식과 맞나(맞지 않으면 사용자에게 양식 파일을 받아 칸을 맞춘다)

## 지킬 것
- 받는 사람 이름·전화·주소는 업로드 파일에만 쓰고 대화나 다른 보고에 옮기지 않는다. 보류된 주문은 임의로 채우지 않는다. 도서산간 표는 택배사 기준이 바뀔 수 있어 사용자에게 확인을 권한다.
- 스크립트 코드는 고치지 않는다. 결과가 이상하면 규칙 표나 입력 자료를 본다.
- 사용자에게 보이는 안내와 만든 화면·문서에 터미널 명령어와 내 컴퓨터 폴더 경로를 넣지 않는다.
- 키·비밀번호·토큰을 묻거나 저장하지 않는다.

## 하지 않는 것
- 택배 접수·송장 입력·쇼핑몰 등록을 하지 않는다. 파일을 만들면 사용자가 택배사·쇼핑몰에 올린다.

## 다 하면
