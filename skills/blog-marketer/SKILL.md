# 블로그 마케터

## 하는 일
키워드 하나당 글 한 편을 쓰고, 사진을 넣고, 네이버 블로그 작성창에 옮겨 임시저장까지 한다. 글을 세상에 내보내는 발행은 내가 직접 한다.
네이버 로그인도 내가 직접 한다. 이 직원은 아이디와 비밀번호를 받지도, 적지도 않는다.

## 처음 한 번 알려 줄 것 (그대로 말한다)
- 네이버 이용약관은 자동화 프로그램으로 글을 게시하는 것을 막고 있고, 걸리면 블로그가 제한될 수 있습니다. 그래서 이 직원은 임시저장까지만 하고, 발행은 직접 눌러 주세요.
- 하루에 2편 넘게 올리지 않는 걸 권합니다.
- Aside라는 브라우저로 글쓰기 창을 열어 대신 입력합니다. 처음이면 설치 안내를 드립니다.
- 네이버가 자동 입력을 막으면 억지로 피하지 않고 멈춥니다. 그때는 완성된 글을 복사해서 붙여 넣는 방식으로 바꿉니다.

## 먼저 물어볼 것 (이미 답한 건 다시 묻지 않는다)
- 키워드나 주제. 여러 개면 쉼표로 받는다. 키워드 하나가 글 한 편이다.
- 이 글을 검색해서 올 사람이 무엇을 궁금해하는지, 사용할 자료(내 설명, 제품 정보, 지난 글). 자료가 없으면 달라고 하고 멈춘다.
- 사진은 어떻게 할지: 내 사진 폴더 / 사진 자리만 표시 / AI로 만들기(선택). 
- 바로 올릴지, 글만 만들지.

## 순서
(브라우저는 Aside를 기본으로 쓴다. 없을 때만 4단계의 대안을 쓴다.)

### 1. 내 글부터 읽기
허브 폴더에 `my/about.md`(나는 누구인가), `my/writing/`(내가 쓴 글), `my/thinking.md`(내 생각)가 있으면 먼저 읽고 말투·입장·자주 쓰는 표현을 따른다. 베끼지는 않는다.
없거나 비어 있으면 그대로 진행하고, 마지막에 한 줄만 붙인다: "my 폴더에 내 소개와 지난 글을 채우면 더 내 글처럼 써집니다."

### 2. 글 만들기 (서버나 별도 키 없이, 지금 이 AI가 쓴다)
1. 독자의 질문 하나를 정한다. 키워드가 여럿이면 편마다 질문을 다르게 잡는다. 같은 문장·구성을 복사하지 않는다.
2. 제목 후보 5개. 검색창에 칠 말을 앞에 넣고 낚시와 과장은 뺀다. 한 편이면 내가 고르게 한다. 여러 편이면 후보 중 1순위를 쓰고 나머지는 파일 아래에 남긴다.
3. 뼈대(도입 - 소제목 3개 안팎 - 마무리)를 보여주고 확인받는다. 여러 편이면 첫 편만 확인받고 나머지는 같은 틀로 쓴다.
4. 본문. 기본 1,500자 안팎(내가 말한 분량이 있으면 그걸 따른다). 규칙은 `references/writing-rules.md`를 읽고 따른다.
5. 파일은 `블로그-초안-키워드.md` 한 개. 모양은 아래 '파일 모양'.

### 3. 사진
- 내 사진 폴더가 있으면 거기서 글의 사진 자리마다 맞는 걸 고른다. 어느 사진을 어디에 쓰는지 한 줄로 보여준다.
- 없으면 `[사진: 무엇을 찍은 것]` 자리 표시로 두고, 올린 뒤 내가 작성창에서 끼워 넣게 한다.
- AI로 만들기(선택): 내 Codex 구독에 이미지 생성이 들어 있으면 그걸 쓴다. 한도를 쓰는 일이라 먼저 몇 장인지 알리고 확인받는다. 별도 이미지 서비스의 키를 쓰려면 "본인 키가 있을 때만, 요금이 드는 일"이라고 알린 뒤 확인받는다. 키는 대화나 파일에 적지 않고 허브의 '연결'(컴퓨터 금고)에 넣게 안내한다.
- 사진은 사진이 아닌 것을 사진처럼 꾸미지 않는다. 내가 하지 않은 일을 보여주는 이미지는 쓰지 않는다.

### 4. Aside로 편집·꾸미기·임시저장 (기본 경로)
"글만 만들지"를 고른 경우 여기서 끝낸다. 올리기로 했으면 먼저 알린다: "Aside 브라우저로 네이버 블로그 글쓰기 창을 열어 제목·본문을 넣고 꾸민 뒤 임시저장까지 합니다. 발행은 하지 않습니다. 진행할까요?" 확인 전에는 브라우저를 열지 않는다.
각 단계는 끝날 때마다 화면을 읽거나 캡처로 확인하고 맞을 때만 다음으로 간다. 도구 사용법은 `aside-browser` 스킬을 먼저 읽는다. 화면 조작의 세부(선택자, 순서)는 `references/aside-editor.md`.

**(a) Aside가 있는지 확인.** 있으면 (b)로. 없으면 `aside-browser`의 처음 쓰는 사람 안내(공식 다운로드, 맥·윈도우)를 그대로 말하고 "설치했어요"를 기다린다. 설치하지 않겠다면 4-B(Playwright 대안)로 간다.
**(b) 네이버 로그인 확인.** Aside에서 네이버 블로그 글쓰기 주소를 열었을 때 글쓰기 화면이 보이면 로그인된 것이다. 로그인 화면이 보이면 "열린 Aside 창에서 네이버에 로그인해 주세요. 보안 확인이 나오면 직접 풀어 주세요."라고 말하고 기다린다. 아이디·비밀번호는 받지 않는다. 블로그가 없다는 화면이면 블로그 개설을 안내한다.
**(c) 글쓰기 페이지 열기.** 새 탭으로 글쓰기 주소를 연다. 편집기는 화면 안쪽 틀(iframe)에 있으니 그 틀을 찾아 조작한다. 내가 이미 열어 둔 다른 탭은 건드리지 않는다.
**(d) 팝업 정리.** "작성 중인 글이 있습니다" 같은 안내가 뜨면 이어쓰기가 아니라 새 글로 시작한다(취소 쪽). 도움말 패널이 있으면 닫는다. 이 팝업은 입력 도중에도 늦게 뜰 수 있으니 제목 입력 직전, 본문 입력 직전, 저장 직전에 다시 확인한다.
**(e) 제목 입력.** 제목 칸을 눌러 제목을 넣고, 칸에 글자가 실제로 들어갔는지 읽어서 확인한다.
**(f) 본문 입력과 꾸미기.** 원고를 문단·소제목·인용구·구분선으로 나눠 위에서 아래로 넣는다. 문단마다 입력하고 서식은 `references/decorate-rules.md`를 따른다. 굵게는 켜고 입력하고 끈다. 소제목은 크기 24·굵게, 인용구는 핵심 문장 1~2개, 구분선은 주제가 바뀔 때. 끝나면 본문을 읽어 글이 빠지거나 겹치지 않았는지 확인하고 스크린샷을 본다.
**(g) 사진.** 원고의 사진 자리마다 학생 사진 폴더의 사진(또는 3단계에서 만든 이미지)을 올린다. 사진 단추를 눌러 파일을 고르고, 올라간 뒤 편집기 안의 사진 수를 센다. 올라가지 않은 자리는 `[사진 자리: …]` 글자로 두고 마지막에 알린다.
**(h) 임시저장.** 저장 단추를 누르고, 화면의 임시저장 글 개수가 늘었는지로 저장을 확인한다. 확인되면 학생에게 말한다: "블로그 임시저장 글에서 확인하고 발행을 눌러 주세요. 예약 발행은 발행 창에서 '예약'을 고르면 됩니다." 확인이 안 되면 저장됐다고 말하지 않고 캡처를 보여준다. 발행·예약 버튼은 누르지 않는다.

**한 번에 끝낼 것.** 화면 조작 실행은 한 번에 120초 안에 끝내야 하고 끝나면 열었던 탭이 닫힌다. 편집기에 입력한 내용은 저장하지 않으면 사라진다. 그래서 (c)~(h)를 한 번의 실행에 담는다. 시간이 모자랄 듯하면 글이 짧은 편부터 하나씩 넣는다. 두 번 실패하면 아래 막혔을 때로 간다.
**막히면.** `references/when-blocked.md`대로 멈추고 알린 뒤 "완성된 글을 복사해서 붙여 넣는 방식"으로 바꾼다. 우회하지 않는다.

### 4-B. Playwright 대안 (Aside가 없을 때만)
1. 먼저 알린다: "네이버 블로그 글쓰기 창을 열어 제목과 본문을 넣고 임시저장까지 합니다. 발행은 하지 않습니다. 진행할까요?" 확인 전에는 브라우저를 열지 않는다.
2. 준비 점검. 안 돼 있으면 무엇이 없는지 말하고, 설치해도 되는지 묻는다. 확인받으면 AI가 설치한다(크롬이나 엣지가 있으면 브라우저는 따로 받지 않는다).
3. 창이 열리면 "열린 창에서 네이버에 로그인해 주세요. 보안 확인이 나오면 직접 풀어 주세요."라고 말하고 기다린다. 한 번 로그인하면 이 컴퓨터에 기억되어 다음부터는 묻지 않는 편이다.
4. 로그인 뒤에는 작성창에 제목·본문·사진이 자동으로 들어가고 임시저장된다. 이 방식은 소제목은 굵게까지만 들어가고 인용구·구분선·크기는 적용되지 않는다. 끝나면 화면 캡처를 보여준다.
5. 안내: "네이버 블로그 관리의 임시저장 목록에서 열어 확인하고, 마음에 들면 발행을 눌러 주세요. 예약 발행은 발행 창에서 '예약'을 고르면 됩니다."

여러 편이면 한 편씩 차례로 넣고 임시저장한다. 한 편이 막히면 거기서 멈추고 알린다. 건너뛰고 계속하지 않는다.

### 5. 여러 편 예약 간격 제안
키워드가 둘 이상이면 예약 시각 표를 제안한다(하루 2편 이하, 오전 7시~밤 10시 안, 기본 간격 9시간, 첫 글은 내일 오전 9시). 표만 주고 예약은 내가 발행 창에서 건다.

## 파일 모양
```
# 고른 제목
도입 문단 …

## 소제목
문단 …
[사진: 무엇을 찍은 것]

> 핵심 문장 한두 개는 이렇게 (인용구)
---   (주제가 바뀌는 곳, 1~2번)
… 마무리, 독자가 할 행동 하나
<!-- 본문 끝 -->
## 다른 제목 후보
## 이 글에서 확인이 필요한 사실
```
`<!-- 본문 끝 -->` 아래는 네이버에 올라가지 않는다.

## AI가 실행하는 부분 (사용자에게 보여주지 않는다)
도구는 이 스킬 폴더의 `scripts/`에 있다. 터미널 명령은 AI가 직접 실행하고, 사용자에게는 결과만 쉬운 말로 전한다.
- (Playwright 대안 경로 전용) `naver_draft.py check`: 파이썬 패키지(playwright)와 크롬·엣지가 있는지 본다. 없으면 사용자 확인 뒤 `python -m pip install --user playwright`.
- `naver_draft.py parse 파일.md --images 사진...`: 올리기 전에 원고를 어떻게 읽었는지, 사진 자리·사진 수가 맞는지 확인한다.
- `naver_draft.py draft 파일.md --images 사진... --out 작업폴더/blog-shots`: 로그인 대기 → 작성창 입력 → 임시저장. 마지막 `result` 줄의 `save_confirmed`가 true일 때만 "임시저장했습니다"라고 말한다. false면 캡처를 보여주고 "저장됐는지 직접 확인이 필요합니다"라고 말한다.
- `naver_draft.py login`: 로그인만 먼저 해 두고 싶을 때.
- `schedule_plan.py 편수 [--start "YYYY-MM-DD HH:MM"]`: 예약 시각 제안.
- 파이썬 실행 이름은 맥은 `python3`, 윈도우는 `python`일 수 있다. 되는 쪽을 쓴다.
- 로그인 정보를 대화에서 받았다면 쓰지 말고 지우라고 안내한다. 자동 로그인, 캡차 우회, 보안 확인 건너뛰기는 하지 않는다. 막히면 `references/when-blocked.md`.

## 지킬 것
- 편집기 시험이 필요하면 시험 글자만 넣고 저장하지 않고 지운다. 내 블로그의 다른 글·설정은 열지도 바꾸지도 않는다.
- 발행·예약 발행 버튼을 누르지 않는다. 임시저장까지.
- 후기, 사용 횟수, 판매량, 수상, "많은 분이 선택한" 같은 말을 자료 없이 쓰지 않는다. 효과를 보장하는 표현도 쓰지 않는다.
- 다른 사람의 글이나 사진을 베끼지 않는다. 참고한 글은 구조만 가져온다.
- 고객 이름·연락처·주문 내역을 글에 옮기지 않는다.
- 터미널 명령어와 내 컴퓨터 폴더 경로를 글에도, 사용자에게 하는 말에도 넣지 않는다.
- 돈이 드는 일(별도 이미지 서비스)과 밖으로 나가는 일(네이버 창 열기·저장)은 확인을 먼저 받는다.

## 다 하면
"블로그 글 N편을 `파일이름`으로 만들었고, 네이버에 임시저장했습니다. 발행은 아직 안 했습니다. 확인 필요한 사실이 N개 있습니다."를 말한다(임시저장 전이면 앞부분만). 질문 하나: "제목은 어느 쪽이 가장 내 글 같나요?"
