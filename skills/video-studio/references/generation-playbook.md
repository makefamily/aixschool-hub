# 영상 생성 플레이북 (Opus 5.5 사례 기반)

기준일 2026-09-27. Opus 5.5 출시(2026-09-22) 후 5일간 X·유튜브·Reddit·GitHub에 올라온 "Opus 5.5로 만든 영상"을 조사했다.
- X 후보 게시물 1,511개, 서로 다른 MP4 1,401개. 공개 카탈로그 [awesome-opus-5-5-videos](https://github.com/athemeroy/awesome-opus-5-5-videos) 기준이다.
- 출처가 확인된 사례 168건
- Aside 직접 수집 X 사례 60건, 유튜브 튜토리얼 22편
- 공개 스킬 저장소 6개를 분석했다.
- 대표 영상 14편은 직접 받아 프레임·컷 속도·라우드니스를 쟀다.

같이 볼 문서: `codefilm-rules.md`, `motion-references.md`(레퍼런스 주소).

## 1. 결론

- **Opus 5.5는 영상을 픽셀로 직접 뽑지 않는다.** 입력은 텍스트·이미지, 출력은 텍스트다. "Opus가 만든 영상"은 모델이 **코드로 프레임을 그리고 렌더러로 MP4를 만든 것**이 대부분이다. 나머지는 외부 영상 모델을 지휘했거나, 기존 영상을 편집했거나, 앱·게임을 녹화한 것이다.
- **퀄리티는 실제로 프로 수준이다.** 직접 본 14편 중 10편이 모션디자인 외주 결과물과 구분하기 어려웠다(§6).
  - 스위스 타이포, 크롬 3D, 수채 질감, 일관된 캐릭터가 나온다.
  - 오디오 트랙이 있는 12편 중 8편이 -16~-13 LUFS로 마스터링돼 있었다(2편은 -16.1~-16.8, 1편 -19.5, 1편 사실상 무음).
- **"원샷"의 실체는 다르다.** 사람의 입력은 한 번이어도, 뒤에서는 에이전트가 15분~12시간 돌며 스스로 렌더·검수·수정한다. 참고 이미지, 기존 스킬, 음원이 같이 들어간 경우가 많다.
- 잘 나온 영상의 공통점은 셋이다: **시간 t의 순수 함수로 그린 프레임, 단일 타이밍 정본(BPM·샷 표), 렌더 후 프레임을 직접 보는 루프.**

## 3. 프롬프트 해부

### 3.1 가장 많이 복제된 프롬프트 (P-A, 쇼릴)

```text
make a dynamic 15-second motion graphics video that shows what an incredible motion designer you are, like it's your showreel for a résumé. go all out.
```

Stephan Livera(1.17M 조회) 이후 수십 명이 그대로 썼다. 변형도 많다:
- "for {제품}"
- "million dollar"
- "Do your research on {제품} first"

**짧은 프롬프트가 통하는 이유**: 목표(쇼릴), 길이(15초), 기준("incredible", "go all out")만 주고 나머지 결정은 모델에 맡긴다. 결과는 매번 스위스 타이포와 챕터 번호, HUD, 이징 시연이 들어간 비슷한 문법이 된다. 차별화가 필요하면 아래 구조형으로 간다.

```text
너는 시니어 모션 디자이너 겸 크리에이티브 코더다. 이 제품으로 [30~45]초 런치 영상을 사운드 포함 MP4로 만들어라. 제품: [URL 또는 폴더].
먼저 제품 페이지와 자료를 읽고 실제로 보여줄 수 있는 기능 3개와 근거 화면을 적어라. 없는 기능·수치·후기는 만들지 마라.
[16:9 1920x1080 | 9:16 1080x1920], 30fps. 모든 프레임은 코드로 그린다(영상 생성 모델·스톡 금지). 폰트는 Pretendard, 색은 [브랜드 색].

승인하면 첫 5초 샘플을 렌더해 컨택트시트로 확인한 뒤 전체를 렌더하라. 오디오는 -14 LUFS, 트루피크 -1 이하.
```

```text
[자료 경로]를 근거로 [주제]를 [대상]이 이해하도록 [60~180]초 설명영상을 만들어라. 학습 목표 3개: [...].

내레이션은 [TTS 이름]. 네가 소리를 직접 들을 수 없으면 "발음 미청취"라고 표시하고 들어볼 시점 3~5개를 적어라.
```

## 4. 제작 루프 (공개 스킬 저장소 공통)

1. **브리프**: 목적·청중·플랫폼·길이·비율·입력 자료·금지 사항을 적는다. 비어 있으면 기본값을 쓴다: 30~45초, 1080², 30fps.
2. **트리트먼트 + 비트시트 (코드보다 먼저)**: 비트마다 끝 상태, 카메라, 노출, 사운드 큐를 적는다. "명사를 그리지 말고 행동과 결과를 계획한다." 모든 비트는 앞 비트가 원인이 된다.
3. **어려운 부분 먼저 증명**: 가장 어려운 한 프레임이나 동작을 먼저 만들어 확인한다.
4. **단일 타이밍 정본**: `BPM, SECTIONS, SHOTS, EVENTS`를 한 곳에 둔다. 그림과 소리가 같은 표를 읽는다. 두 번째 타이밍 상수 금지.
5. **샘플 렌더 → MP4로 확인**: 깜빡임·뭉개짐·비트레이트 문제는 MP4에서만 보인다.
6. **전체 렌더 → 픽셀 검수**: 컨택트시트, 빠른 구간 스트립, 1:1 크롭, 인코딩된 MP4 시트 순으로 본다. "exit 0은 아무것도 증명하지 않는다."
7. **사운드**: 그림 타임라인에서 파생한다. 접촉 약 30ms 전에 두고, 늦어도 40ms 이내, 20ms보다 먼저 두지 않는다.
8. **납품**: 프레임 수 = 길이×fps를 검사한다. BT.709 태그, faststart, 플랫폼 해상도 정확히.
9. **보고**: 무엇을 보고·들었는지, 무엇을 못 했는지 적는다. 소리를 못 들었으면 사람이 들을 시점 3~5개를 지목한다.

## 5. 기술 규칙 (코드 렌더 영상)

**렌더 계약**
- 모든 프레임은 `draw(frame)` 또는 `seek(t)`의 순수 함수다.
- 금지: `Math.random`, `Date`, `requestAnimationFrame` 상태, CSS 애니메이션, 누적 물리.
- 난수는 이름 키로 시드한다: `rngFor("ant/body")`. 프레임 번호로 시드하지 않는다.
- 떨림(boil)은 의도적으로만, 초당 7.5~12회(4프레임마다 시드 교체). 매 프레임 떨리게 하지 않는다.
- 실시간 화면 녹화 금지(프레임 드롭). 인코딩은 임시 폴더에서 하고 성공한 뒤에만 교체한다.

**움직임**
- Snap, then hold: 변화 자체는 0.04~0.07초, 이징은 안착 구간에만 둔다.
- 컷 길이 0.8~2.7초, 스태거 0.05~0.14초.
- 핵심 비트는 샷 가운데. 동작 도중에 들어가고, 마지막 비트에서 나온다.
- 0프레임부터 밝고 움직이는 화면으로 시작한다. 검정에서 페이드인하지 않는다. 마지막 이벤트 뒤에는 읽을 시간을 둔다.
- 컷은 정보를 더할 때만 쓴다. 같은 걸 크게 보려면 카메라를 움직인다.
- 빠른 이동에는 셔터 샘플 모션블러(3px당 1샘플, 최대 10~24)를 쓴다. 공간 안티앨리어싱은 2배로 그려 lanczos로 축소한다.

**디자인**
- 요소는 적게, 렌더링은 풍부하게. 표면은 base→texture→edge 세 층.
- 텍스트 블록 위치는 영상 전체에서 하나로 고정한다. 1080 폭 기준 본문 약 44px, 제목 64~80px, 줄 길이 800px 이하.
- 텍스트끼리 겹치면 안 된다(layout-check로 CLEAN 확인).
- 스타일 바이블은 매 세션 원문 그대로 붙인다. 바꿔 쓰면 스타일이 흔들린다.

**사운드**
- 기본은 Web Audio `OfflineAudioContext`, 48kHz 스테레오, 영상과 정확히 같은 길이.
- 라우드니스는 렌더 후 정적 게인 또는 loudnorm 한 번으로 맞춘다: -16~-14 LUFS, TP -1 이하. 컴프레서로 맞추지 않는다.
- 컷은 볼륨이 아니라 화성 변화로 표시한다. +6dB 넘는 점프는 놀람(STARTLE)으로 FAIL.
- 레이어는 한 마디에 1~2개씩 더한다. 연필 긁는 소리 같은 연속 배경음은 금지, 접촉에만 소리.
- 사용자 음원은 손대지 않는다. 자르는 곳은 zero crossing.

**업로드**
- 30fps, 업로드본에 움직이는 그레인 금지(인스타에서 품질 1/3 손실 실측).
- 플랫폼 해상도 정확히, BT.709 TV range.

## 7. 실패·한계 패턴

- "15초" 요청에 26~30초 결과 → 렌더 후 길이 게이트(`qa_check.sh`)로 잡는다.
- TTS 부자연 → 내레이션은 사람 녹음이나 검증된 음성을 쓴다. 에이전트는 "미청취"를 표시한다.
- 일본 애니메이션·사람 연기는 코드 렌더로 어렵다(작성자 스스로 모션그래픽으로 후퇴한 사례) → 경로 B를 쓰거나 범위를 바꾼다.
- 가사·자막 싱크가 후반에 밀림 → 단일 타이밍 정본과 sync-check를 쓴다.
- 코드 렌더와 생성 모델 결과를 섞고 "코드로 만들었다"고 표기 → 공개 설명에 경로를 정확히 쓴다.
- 비용: $2(1분 코드 영상)부터 $81(Blender 92분)까지. 구독 사용량 1~13%, Max 주간 한도의 7% 등 게시자 보고. 영상 생성 모델 경로는 크레딧이 별도로 든다.
