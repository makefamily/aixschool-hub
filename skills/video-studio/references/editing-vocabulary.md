# 영상 편집 키워드: AI에게 원하는 결과를 설명하는 법

확인일: 2026년 11월 8일. Aside로 공개 공식 문서를 조사했습니다.

용어를 외우는 목적은 ‘어느 구간을 어떻게 바꾸면 되는지’ 말할 수 있게 되는 것입니다. **대상 구간 → 원하는 변화 → 정도 → 보존할 것 → 확인 방법**을 함께 적으면 편집 지시가 구체적이 됩니다.

예를 들어 “빠르고 감각적으로” 대신 이렇게 말합니다.

> 원본 00:02:10–00:02:40의 같은 설명이 반복되는 부분을 줄여줘. 정확하게 다시 말한 문장을 사용하고, 조건과 예외는 남겨줘. 컷 사이 호흡이 끊기지 않는지 듣고, 삭제한 원본 타임코드를 알려줘.

범위는 강의·설명형 유튜브·세로 쇼츠의 편집입니다. 아래 지시문은 직접 구성한 예시이며, 특정 AI 도구의 기능 지원을 뜻하지 않습니다. 숫자는 별도 표시가 없으면 시안용 편집 선택값입니다.

| 말을 자연스럽게 연결하기 | J컷, L컷 | “다음 장면 소리가 화면보다 먼저 시작하게 해줘.” |
| 말에 맞는 보충 화면 넣기 | B롤 | “설명하는 제품을 보여주되 설명 음성은 이어줘.” |
| 중요한 말 강조하기 | 펀치인 | “핵심 문장에서만 얼굴을 살짝 확대해줘.” |
| 화면 움직이기 | 키프레임 | “메뉴 위치로 이동했다가 전체 화면으로 돌아와줘.” |

| 말과 음악 균형 잡기 | 덕킹 | “말할 때 배경음악을 낮추고 문장 사이에서 회복해줘.” |
| 컷마다 다른 색 맞추기 | 색보정 | “노출과 피부색이 컷마다 튀지 않게 맞춰줘.” |
| 세로로 바꾸기 | 리프레이밍 | “얼굴과 시연의 중요한 부분을 유지하며 세로로 재구성해줘.” |

12개를 전부 익히지 않아도 됩니다. 반복 삭제와 자막부터 적용한 뒤, 화면·소리·색 순서로 넓혀보세요.

## 1. 자르고 연결하기

| 번호·용어 | 뜻·보이는 변화 | AI 지시 예시 | 혼동 주의 |
|---|---|---|---|
| 01 컷·하드컷 / Cut, hard cut | 한 화면에서 다른 화면으로 바로 바뀜. 문맥에 따라 클립을 분할하는 작업도 컷이라 부름. | “주제 전환 지점에서 다음 장면으로 하드컷해줘.” | ‘여기 컷’은 분할인지 삭제인지 모호함. 원하는 작업을 함께 말하기. |
| 02 트림 / Trim | 클립의 시작·끝 경계를 조절함. | “인사 전 준비 시간을 시작점에서 트림해줘.” | 가운데 구간 삭제, 뒤 클립 당김 여부는 별도 지정. |
| 03 점프컷 / Jump cut | 비슷한 구도의 시간 일부가 생략되어 인물·동작이 튀어 보이는 연결. | “반복 발언은 점프컷으로 줄이되 말뜻과 호흡을 유지해줘.” | 모든 하드컷이 점프컷은 아님. |
| 04 매치컷 / Match cut | 모양·동작·구도 등의 유사성을 이용해 장면을 연결함. | “원형 시계에서 원형 제품으로 형태가 맞는 매치컷을 만들어줘.” | 단순한 장면 전환이나 컷 간 색상 맞추기와 다름. 적합한 소스가 필요함. |
| 05 J컷 / J-cut | 다음 장면의 소리를 먼저 들려주고 화면이 뒤따름. | “다음 인터뷰 음성이 먼저 시작되고 그 사람 화면으로 전환되게 해줘.” | 새 소리가 먼저. 현재 장면 소리를 남기는 L컷과 구별. |
| 06 L컷 / L-cut | 현재 장면의 소리를 다음 화면까지 이어둠. | “설명자의 음성을 유지한 채 제품 시연 화면으로 바꿔줘.” | 이전 소리가 남음. 오디오·비디오 분리 후 싱크도 확인. |
| 07 리플 편집 / Ripple edit | 길이를 바꾸면 뒤의 타임라인도 당기거나 밀어 조정함. | “이 공백을 리플 삭제하고 뒤에 빈 구간이 남지 않게 해줘.” | 잠긴 트랙·연결 오디오·후반 음악과의 관계도 확인. |
| 08 롤링 편집 / Rolling edit | 인접한 두 클립의 경계를 옮기되 두 클립의 합계 길이는 유지함. | “전체 길이는 유지하고 다음 화면이 조금 일찍 나오게 경계를 롤링해줘.” | 리플과 달리 경계 양쪽이 상쇄됨. 원본 여유분이 있어야 함. |
| 09 슬립 / Slip | 타임라인의 자리와 길이를 유지하고 클립 안에서 사용할 원본 범위를 바꿈. | “이 3초 B롤의 위치는 유지하고 제품이 잘 보이는 원본 부분으로 슬립해줘.” | 클립의 위치를 옮기는 작업이 아님. |
| 10 슬라이드 / Slide | 클립 자체의 길이·내용을 유지하며 위치를 바꾸고 양옆 클립 경계를 조정함. | “가운데 시연 클립을 조금 뒤로 슬라이드하고 앞뒤 길이를 조정해줘.” | 단순 드래그 이동과 다름. 주변 클립의 원본 여유가 필요함. |

J컷과 L컷은 소리의 주인이 누구인지 보면 쉽습니다.

| 연결 방식 | 화면이 바뀌기 전 | 화면이 바뀐 뒤 |
|---|---|---|
| J컷 | A 화면에서 **B의 소리가 먼저 시작** | B 화면과 B 소리 |
| L컷 | A 화면과 A 소리 | B 화면에서도 **A 소리가 이어짐** |

## 3. 구도·움직임·전환 조절하기

| 번호·용어 | 뜻·보이는 변화 | AI 지시 예시 | 혼동 주의 |
|---|---|---|---|
| 17 크롭 / Crop | 화면 일부를 잘라 표시 범위를 좁힘. | “화면 가장자리의 불필요한 공간을 크롭해줘.” | 확대·재배치와 같이 쓰이지만 동일한 작업은 아님. |
| 18 리프레이밍 / Reframing | 피사체와 정보를 고려해 구도를 다시 잡음. | “가로 시연을 세로로 바꾸되 핵심 버튼과 결과를 함께 보여줘.” | 단순 중앙 크롭으로 해결되지 않을 수 있음. 자동 추적 지원은 도구마다 다름. |
| 19 펀치인 / Punch-in | 같은 원본에서 더 가까운 구도로 잘라 강조함. | “핵심 한 문장에서만 기본 구도보다 약 10% 확대하는 시안을 보여줘.” | 원본 해상도에 따라 선명도가 떨어짐. 광학 줌과 다름. |
| 20 키프레임 / Keyframe | 시간별 위치·크기·불투명도 등의 값을 지정함. | “2초 동안 전체 화면에서 메뉴 영역으로 이동·확대해줘.” | 위치·시간·시작값·끝값이 있어야 움직임이 구체적임. |
| 21 이징 / Easing, ease in/out | 변화의 시작·끝 속도를 부드럽게 조절함. | “확대는 천천히 시작해 움직이고 끝에서 부드럽게 멈춰줘.” | 움직임의 궤적과 속도 변화는 별개의 조절 요소임. |
| 22 디졸브·페이드 / Dissolve, fade | 화면끼리 겹치며 바뀌거나 한 화면이 색·투명으로 사라지거나 나타남. | “시간 경과 구간만 디졸브로 연결하고 마지막은 검정으로 페이드아웃해줘.” | 모든 컷에 넣지 않기. 전환 전후 원본 여유분도 확인. |
| 23 스피드 램프 / Speed ramp | 재생 도중 속도가 점차 변함. | “이동 장면만 빠르게 하고 도착 순간에는 정상 속도로 복귀해줘.” | 일정 배속과 다름. 설명 음성에 적용하면 전달력이 손상될 수 있음. |
| 24 슬로모션·보간 / Slow motion, interpolation | 천천히 재생하며 필요한 중간 프레임을 반복·혼합·추정할 수 있음. | “동작을 느리게 보여주고 보간으로 손가락이 찌그러지지 않는지 검수해줘.” | 옵티컬 플로는 없는 프레임을 추정하는 방식 중 하나. 원본 고속촬영과 같지 않음. |

## 5. 말소리·음악 다듬기

| 번호·용어 | 뜻·들리는 변화 | AI 지시 예시 | 혼동 주의 |
|---|---|---|---|
| 29 게인 / Gain | 신호 레벨을 올리거나 내리는 조절. | “작게 녹음된 구간의 게인을 올리고 클리핑이 생기지 않는지 확인해줘.” | 볼륨과 유사한 결과가 날 수 있지만 처리 위치가 다를 수 있음. |
| 30 정규화 / Normalization | 정한 피크 또는 라우드니스 목표에 맞춰 레벨을 조정함. | “피크 기준인지 통합 라우드니스 기준인지 밝히고 정규화해줘.” | 한 번의 레벨 조정이 구간별 음량 차이를 모두 해결하지는 않음. |
| 31 라우드니스·LUFS / Loudness, LUFS | 사람이 느끼는 음량에 가깝게 계측하는 개념·단위. | “완성본 전체의 integrated LUFS를 측정하고 전후 값을 보고해줘.” | 순간·단기·통합 값을 구분. 특정 LUFS를 모든 플랫폼 의무값으로 쓰지 않기. |
| 32 트루피크·클리핑 / True peak, clipping | 트루피크는 샘플 사이 재구성 피크까지 추정. 클리핑은 허용 범위를 넘으며 생기는 왜곡. | “트루피크를 확인하고 출력 변환 뒤에도 찌그러지는 소리가 없는지 들어줘.” | 샘플 피크와 트루피크는 같지 않음. 리미터를 과하게 쓰면 음질이 바뀜. |
| 33 덕킹 / Ducking | 말 등 기준 신호가 있을 때 음악 등의 레벨을 낮춤. | “말할 때 음악을 낮추고 문장 사이에는 부드럽게 회복해줘.” | 음악을 전 구간 일정하게 작게 하는 것과 다름. |
| 34 오디오 페이드·크로스페이드 / Fade, crossfade | 시작·끝을 점차 바꾸거나 두 오디오를 겹쳐 연결함. | “음악 끝은 페이드아웃하고 편집점에서 튀는 소리를 부드럽게 연결해줘.” | 긴 겹침은 대사를 중복시킬 수 있음. |
| 35 노이즈 제거 / Denoise, noise reduction | 지속 잡음 등을 줄여 말소리를 명확히 함. | “에어컨 소리를 줄이고 목소리의 금속성·울렁임이 생기면 강도를 낮춰줘.” | 잡음·반향·다른 사람 말소리 제거는 다른 문제이며 완벽 제거가 보장되지 않음. |
| 36 룸톤 / Room tone | 해당 장소의 자연스러운 배경 소리. | “잘라낸 지점이 갑자기 무음이 되면 같은 장소의 룸톤으로 자연스럽게 이어줘.” | 배경음악이나 새 효과음과 다름. |
| 37 싱크 / Sync | 입 모양·동작과 해당 소리의 시점을 맞춤. | “외부 녹음과 입 모양을 맞추고 영상 뒤쪽에서도 싱크가 유지되는지 확인해줘.” | 처음 한 지점이 맞아도 긴 영상에서는 점차 어긋날 수 있음. |

## 6. 색과 밝기 맞추기

|---|---|---|---|
| 38 색보정 / Color correction | 노출·색온도·컷 간 차이 등을 맞춰 기초 상태를 정리함. | “이어지는 컷들의 밝기와 피부색이 튀지 않게 보정해줘.” | 스타일을 만드는 그레이딩과 목적상 구분하지만 실제 작업은 겹칠 수 있음. |

| 41 노출·하이라이트·섀도 / Exposure, highlights, shadows | 전체 밝기와 밝고 어두운 영역을 조절함. | “얼굴은 읽히게 밝히고 밝은 화면의 글자가 날아가지 않게 해줘.” | 원본에서 잃은 디테일을 항상 복원할 수 있는 것은 아님. |
| 42 LUT / Look-up table | 입력 색값을 정해진 출력값으로 바꾸는 변환표. | “원본 색공간·감마에 맞는 LUT인지 확인하고 적용 전후를 비교해줘.” | 기술 변환 LUT와 룩 LUT의 목적이 다름. 만능 자동보정 필터가 아님. |
| 43 색공간·HDR/SDR / Color space, HDR/SDR | 색과 밝기의 표현·해석 방식 및 범위와 관련됨. | “원본 HDR 여부를 확인하고 요청한 SDR 출력에서 밝기와 색이 틀어지지 않게 변환해줘.” | 해상도와 다른 개념. 태그·감마·출력 관리도 함께 확인해야 함. |

## 7. 파일과 출력 조건 정하기

| 번호·용어 | 뜻·결과에 미치는 영향 | AI 지시 예시 | 혼동 주의 |
|---|---|---|---|
| 44 화면 비율 / Aspect ratio | 가로와 세로의 비. 16:9·9:16 등이 있음. | “세로 9:16으로 재구성하되 시연 정보가 빠지면 배치를 바꿔줘.” | 비율만으로 픽셀 수가 정해지지 않음. |
| 45 해상도 / Resolution | 한 프레임의 가로·세로 픽셀 수. | “세로 1080×1920으로 내보내고 작은 글자의 선명도를 확인해줘.” | 큰 출력 픽셀 수만으로 원본 세부 정보가 늘지는 않음. |
| 46 프레임레이트 / Frame rate, FPS | 1초에 표현하는 프레임 수. | “원본 FPS와 프로젝트·출력 FPS를 확인하고 변환이 필요하면 방식을 알려줘.” | 24·25·30·60 및 소수 FPS를 임의로 동일 취급하지 않기. |
| 47 코덱·컨테이너 / Codec, container | 코덱은 압축·해독 방식, 컨테이너는 영상·소리·메타데이터를 담는 파일 구조. | “목적지에서 지원하는 MP4 컨테이너와 H.264 코덱으로 출력해줘.” | MP4와 H.264는 같은 층위가 아님. 소리 코덱도 별도 확인. |
| 48 비트레이트 / Bitrate | 시간당 쓰는 데이터량. 화질·파일 크기에 영향을 줌. | “해상도·FPS·움직임과 플랫폼 지침을 보고 비트레이트를 정해줘.” | 높을수록 원본보다 좋아지는 것은 아님. VBR/CBR 등 방식도 구분. |
| 49 프록시 / Proxy | 편집을 가볍게 하기 위한 원본 대체본. | “편집은 프록시로 진행하고 최종 출력은 원본과 연결된 상태인지 확인해줘.” | 낮은 화질 프록시가 실수로 최종본에 쓰이지 않도록 확인. |
| 50 타임코드 / Timecode | 원본·타임라인의 특정 시간을 가리키는 주소. | “삭제 지점은 원본 기준, 결과 위치는 출력본 기준으로 각각 적어줘.” | 자른 뒤 원본 시간과 출력 시간은 달라짐. 프레임식 표기는 FPS도 필요. |
| 51 렌더링·내보내기 / Rendering, export | 효과 등을 계산하고 결과 파일을 생성하는 과정. | “출력 파일을 다시 열어 길이·자막·음량·마지막 프레임을 확인해줘.” | 앱의 성공 메시지만으로 파일 재생·내용 검수가 끝나는 것은 아님. |

|---|---|

| “유튜브 느낌으로.” | “주제 전환은 하드컷, 핵심 문장만 펀치인, 관련 시연은 B롤로 넣어줘.” |
| “자막 예쁘게.” | “폰트·크기·정렬·색을 통일하고 두 줄을 시작 기준으로 모바일 가독성을 확인해줘.” |
| “음악은 알아서.” | “대화가 우선이고 말할 때 덕킹해줘. 음악 시작과 끝은 자연스럽게 페이드해줘.” |
| “쇼츠로 압축해줘.” | “한 가지 주장만 골라 독립적으로 이해되게 구성하고 부정·조건·예외를 유지해줘.” |

## 수치는 이렇게 지정하기

- **원본에서 확인할 사실:** 길이, 해상도, FPS, 음성 트랙, HDR 여부. 모르면 파일에서 확인합니다.
- **작업자가 고를 편집값:** 침묵 후보 0.8초, 확대 약 10%, 전환 0.3초, 자막 두 줄 등. 시안으로 확인하고 조정합니다.
- **계측할 품질값:** integrated LUFS, true peak, 프레임 누락·싱크 등. 실제로 측정한 값과 목표를 구분합니다.
- **게시 시점에 확인할 조건:** 허용 형식, 업로드 제한, 플랫폼별 UI·인코딩 지침. 공식 안내에서 다시 확인합니다.

“모든 침묵 삭제”, “항상 2초마다 컷”, “어떤 영상이든 특정 LUFS”처럼 맥락을 지우는 일괄 규칙은 피하세요. 강의의 기다림과 쇼츠의 대기 구간은 역할이 다릅니다.

## 20분 학습 순서

| 시간 | 할 일 | 이해했는지 확인하는 질문 |
|---|---|---|
| 0–5분 | 컷·트림·리플·점프컷·J컷·L컷 읽기 | “말은 이어가고 화면만 바꾸려면 어떤 지시가 필요한가?” |
| 5–10분 | B롤·펀치인·키프레임·리프레이밍 읽기 | “핵심 버튼을 보여주면서 세로 화면을 만들려면 무엇을 보존해야 하는가?” |
| 10–15분 | 자막·안전영역·덕킹·LUFS 읽기 | “자막 위치와 음량이 괜찮다는 것을 어떻게 확인할 것인가?” |
| 15–20분 | 아래 템플릿에 실제 영상 조건 넣기 | “어느 구간에 무엇을 얼마나 적용하고 무엇을 남길지 적었는가?” |

정답 예시: ① L컷 또는 설명 음성을 유지한 B롤, ② 버튼·결과·얼굴 등 정보 우선순위를 지정한 리프레이밍, ③ 실제 모바일 표시와 귀로 듣기·가능한 계측을 함께 확인, ④ 원본 기준 타임코드와 보존 조건을 포함한 지시문.

## 바로 사용할 지시문

**출력값 예시:** 확인한 YouTube 안내는 SDR 1080p의 권장 영상 비트레이트를 24·25·30fps에서 8Mbps, 48·50·60fps에서 12Mbps로 제시합니다. 이는 해당 조건의 권장값이며 의무값·업로드 상한이 아닙니다. 이 예시를 다른 플랫폼·HDR·다른 해상도에 그대로 옮기지 마세요. [공식 인코딩 안내](https://support.google.com/youtube/answer/1722171?hl=en)
