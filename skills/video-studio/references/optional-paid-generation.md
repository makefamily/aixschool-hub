# 선택: 유료 영상 생성 도구로 코드가 못 하는 부분 채우기

**이 단계는 선택이다. 학생 본인 구독·키가 있을 때만 쓴다.** 없으면 건너뛰고 코드(code-film·HyperFrames·Remotion)나 학생이 가진 영상·이미지로 만든다.
쓰기 전에 매번 (1) 어떤 도구·계정인지 (2) 몇 편·몇 초를 만들지 (3) 구독 한도 또는 과금(초당 요금) (4) 외부 서버로 나가는 자료를 학생에게 알리고 **확인을 받은 뒤** 시작한다. 확인 없이 재시도하지 않는다. 키·로그인은 학생이 직접 한다(대화·파일에 적지 않는다).
아래는 Grok Imagine(xAI)을 쓴 2026-09-27 조사·실측이다. Seedance·Veo·Runway 같은 다른 영상 모델도 같은 나눔(코드는 글자·UI·타이밍, 생성 모델은 움직임·소재)과 같은 게이트를 따른다. 도구 사양·요금은 바뀌므로 쓰기 전에 공식 문서로 다시 확인한다.

## 0. 원칙: 나눠 맡긴다

| 맡는 쪽 | 하는 일 |
|---|---|
| 코드(code-film, Remotion, FFmpeg) | 글자, 숫자, UI 화면, 로고, 레이아웃, 타이밍, 박자 싱크, 브랜드 색, 최종 조립 |
| Grok Imagine | 살아 있는 움직임(사람·천·연기·물·불·빛), 내 그림에 생기 주기, 실사 B롤, 두 장면을 잇는 형태 변화 |

- 생성 컷은 재료다. 완성본을 한 번에 뽑으려 하지 않는다. 조립·자막·색·소리는 우리 흐름(E·G)에서 한다.
- 생성 컷의 소리는 기본적으로 버린다. 음악·효과음 정본은 우리 SCORE나 믹스다.

## 1. 두 경로

| | A. Grok Build CLI (본인 구독이 있을 때) | B. xAI API (유료, 본인 키) |
|---|---|---|
| 과금 | SuperGrok 구독 안에서 씀. 한도를 소모함 | 공식 표기: 영상 1.5 초당 $0.08, 이미지 2.0 장당 $0.04. 실청구 미확인 |
| 이미지 | `image_gen`(prompt, aspect_ratio), `image_edit`(prompt, image 여러 장, aspect_ratio) | `grok-imagine-image-2.0`, 영역 편집, 세그멘테이션, 배경 제거(투명) |
| 영상 | `image_to_video`(image 1장=첫 프레임, prompt 생략 가능, duration 6·10초, resolution_name 480p 기본·720p), `reference_to_video`(prompt·aspect_ratio 필수, images 최대 7장, voices 최대 3개 `<AUDIO_0>`, 1~15초, 480p·720p). 텍스트만으로 만드는 도구 없음. **CLI 영상은 최대 720p** | 텍스트·이미지·레퍼런스→영상, 1~15초, 480p·720p·1080p, `last_frame`·`keyframes`(최대 4), 영상 편집(720p·8.7초 상한), 연장 |
| 근거 | 2026-09-27 로그인 후 도구 정의 실측 | docs.x.ai 영상 생성·편집 문서 |
| 쓸 때 | 평소 전부 | 첫·마지막 프레임 고정, 키프레임, 1080p가 꼭 필요할 때만. 비용 보고 후 승인 |

- 도구 정의에 워터마크·소리 옵션은 없다. 결과 fps·소리 포함 여부·워터마크는 첫 생성 때 `ffprobe`와 프레임으로 확인한다.
- 720p 결과를 1080x1920에 쓰면 1.5배 확대된다. 선화·글자가 없는 배경·소재 용도가 안전하고, 전면 주인공 컷은 확대 흐림을 확인한다.
- 로그인은 학생 본인 계정으로 한다. 로그인이 풀리면 `grok login`을 안내한다.
- 구독 하루 한도는 공식 출처가 없다. 블로그의 "하루 50편"은 믿지 말고 실측으로 적는다.

## 2. 편집에 쓰는 8가지

1. **우리 그림에 숨 불어넣기.** 인스타 패널·캐릭터 컷을 `image_to_video` 6초로 만든다. 카메라만 움직이거나(천천히 밀기, 패럴랙스), 동작 하나만 준다(깜빡임, 타이핑). 선화는 움직이면 형태가 무너지기 쉬우므로 카메라 이동을 기본으로 한다. 쓰는 곳: 코드 영상의 정지 그림판 자리.
2. **장면 사이 형태 변화 전환.** 두 장면의 끝과 시작 프레임을 잇는 영상이다. API는 `image`+`last_frame`으로 정확히 만든다. CLI는 이전 컷 마지막 프레임을 뽑아(`ffmpeg -sseof -0.05 -i a.mp4 -frames:v 1 last.png`) 다음 컷의 첫 프레임으로 쓴다.
3. **코드로 못 그리는 소재 클립.** 잉크 번짐, 연기, 빛샘, 불꽃, 물, 종이 찢김, 먼지 파티클. 검정 배경으로 만들고 스크린 합성한다: `ffmpeg -i base.mp4 -i fx.mp4 -filter_complex "[0][1]blend=all_mode=screen" out.mp4`. 초록 배경은 생성물에 초록이 번져 키잉 품질이 들쭉날쭉하므로 두 번째 선택이다.
4. **실사 B롤·인서트.** 밤 가게 풍경, 알림 뜨는 휴대폰을 든 손, 주방 손동작. 토킹헤드 편집(E 경로)의 인서트 컷으로 쓴다. 실존 인물은 만들지 않는다. 우리 인물이 필요하면 본인 사진을 레퍼런스로 `image_edit`한다.
5. **캐릭터 일관성.** 기준 이미지 1장을 먼저 정한다. 컷마다 `image_edit`으로 첫 프레임을 만들고 `image_to_video`로 움직인다. 같은 캐릭터를 `image_gen`으로 새로 뽑지 않는다(매번 얼굴이 달라진다).
6. **쇼츠 첫 3초 훅.** 강한 비주얼 한 컷만 생성하고, 훅 문장은 코드로 얹는다.
7. **루프·스프라이트.** Grok 번들 `game-animation-frames` 방식이다. 6초 영상에서 `fps=12`로 프레임을 뽑고, 한 주기가 이어지는 구간만 골라 루프 소재로 쓴다(걷기, 깃발, 불, 반짝임).
8. **로고·엔드 스팅 배경.** 로고와 글자는 코드로 그린다. 뒤의 에너지(빛, 입자, 천)만 생성한다.

## 3. 맡기지 않는 것

한글을 포함한 글자, 숫자, 차트, UI 화면, 로고 재현, 여러 동작이 이어지는 긴 컷, 실존 인물, 고객 자료·미공개 자료가 담긴 이미지(외부 서버로 전송됨).

## 4. 표준 흐름

1. **비트시트에 G컷 표시.** 컷마다 첫 프레임 출처, 동작 한 줄, 카메라, 길이(6 또는 10초), 용도(그림판·소재·B롤·전환)를 적는다.
2. **첫 프레임 준비.** 우리 자산에서 시작하고, 비율은 이미지 단계에서 맞춘다(9:16이면 9:16 이미지). 복잡한 그림은 단순하게 다듬어 넘긴다.
3. **프롬프트.** 현재형 1~2문장. 주체, 동작 하나, 카메라 움직임 하나, 빛. 예: `The cartoon shop owner sits on the sofa at night, phone glowing on his face; slow push-in, everything else still.`
4. **생성.** 작업 폴더에서 비대화로 돌린다. 명령 형태는 로그인 후 실측해 확정한다.
   ```bash
   mkdir -p work/grok && cd work/grok
   grok -p "첫 프레임 ../frames/g01.png 로 image_to_video 6초 1편만 만들고 결과를 g01.mp4 로 저장해. 다른 생성은 하지 마." --always-approve
   ```
   생성 편수는 프롬프트에 못 박는다(에이전트가 알아서 여러 번 뽑지 않게).
5. **수집·표준화.** `ffprobe`로 해상도·fps·길이·소리를 기록한다. 우리 규격으로 맞춘다:
   `ffmpeg -i g01.mp4 -vf "fps=60,scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920" -an -c:v libx264 -crf 16 -pix_fmt yuv420p g01_norm.mp4`
6. **조립.**
   - 생성 영상이 들어가는 작품은 Remotion(`<OffthreadVideo>`)으로 조립하는 것을 기본으로 한다. code-film은 단일 HTML·외부 자산 0 원칙이라 영상 레이어에 맞지 않는다.
   - 인서트만 넣는 편집은 E 경로의 EDL에 B롤 구간으로 넣는다.
   - 소재 클립은 FFmpeg 스크린 합성으로 넣는다.
7. **QA.** 생성 컷마다 컨택트시트를 만들어 손·얼굴·선 형태 붕괴, 글자 생김, 워터마크, 첫 프레임 대비 색 이탈을 본다. 이후 공통 QA 게이트(`qa-gate.md`)를 통과해야 한다.

## 5. 비용과 게이트

- CLI 생성도 구독 한도를 쓴다. 몇 편을 어디에 쓸지 먼저 보고하고 승인받는다.
- API는 유료다. 계산 예: 6초 컷 5개는 30초 × $0.08 = $2.4(공식 표기 기준). 실제 청구 1회로 단가를 확정한다.
- 모더레이션에 막히면 표현을 바꿔 재시도하지 않는다. 막혔다고 보고한다.
- 광고에 쓰기 전에 상업 이용 조건과 워터마크를 확인한다(미확인).
- 우리 그림을 xAI 서버로 보낸다. 공개된 자산만 보낸다.
