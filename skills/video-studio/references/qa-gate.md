# QA 게이트

"렌더됐다"는 완료가 아니다. 아래 A~D를 모두 통과하고, 보고서에 실제 출력 캡처를 붙인 뒤에만 완료를 보고한다. 자동 검출은 후보이며 자동 수정은 하지 않는다.

## A. 기술 검사 (스크립트: `scripts/edit/qa_check.sh <final.mp4> [목표초] [허용오차초]`)

| 검사 | 명령 | 통과 기준(시작값) |
|---|---|---|
| 스트림·길이 | `ffprobe -show_entries format=duration:stream=codec_name,width,height,r_frame_rate,pix_fmt,sample_rate,channels` | 목표 해상도·fps·yuv420p·48kHz, 길이 = 목표 ± 허용오차 |
| 라우드니스 | `ffmpeg -i f -af ebur128=peak=true -f null -` | I = 목표 ±1 LU, TP ≤ -1 dBTP |
| 블랙 프레임 | `blackdetect=d=0.10:pix_th=0.04` (0.10은 짙은 남색 배경을 검정으로 오탐 — 실측) | 의도된 페이드 외 0건 |
| 정지 프레임 | `freezedetect=n=-60dB:d=2` | 의도된 정지 외 0건 |
| 무음 | `silencedetect=noise=-45dB:d=0.8` | 의도된 멈춤 외 0건 |
| 클리핑 | `astats=metadata=1:reset=0` | Peak < 0 dBFS, 연속 풀스케일 샘플 0 |
| 시작·끝 | 첫/끝 1초 캡처 | 첫 프레임 검정·끝 빈 프레임 없음 |
| faststart | `ffprobe -v trace f 2>&1 \| grep -m1 -o 'type:.moov\|type:.mdat'` | moov가 먼저 |
| 색 태그 | `color_primaries/transfer/space` | bt709 3종 일치, yuv420p TV range |
| 대사 보존 | `roundtrip_check.py final.mp4 edl.json` (Whisper가 설치된 python) | 일치율 0.95 이상, 누락 어절 0 (촬영본 편집일 때) |
| 남은 반복·다시 말함 | `retake_check.py final.mp4` (Whisper가 설치된 python, 85초 영상 약 75초) | 확정 0건 (촬영본 편집일 때 필수). 강조로 남긴 반복은 `--allow 낱말` + EDL reason. 의심 항목은 보고서에 시각을 적고 사람이 들어본다 |
| 코드 영상 계약 | `asset-audit.mjs`, `layout-check.mjs`, `sync-check.mjs`, `render.mjs page.html --check` (engines/code-film, 작업 폴더에서 node로 실행. 소리 없는 영상은 sync-check 생략 가능) | CLEAN, 텍스트 겹침 0, 소리 큐 ±100ms·놀람 점프 0, DETERMINISM PASS(루프 영상은 LOOP SEAM 1% 미만) |

## B. 시각 검사

추출해서 직접 본다(이미지 Read).
- 시작·25%·50%·75%·끝 프레임
- 모든 전환의 시작·중간·끝
- 가장 긴 자막, 가장 긴 제목·로어서드 (잘림·줄바꿈·겹침)
- 숫자·차트가 보이는 프레임 (대본 수치와 대조)
- 세로 영상: 하단 캡션 영역·오른쪽 버튼 열에 텍스트가 없는지
- 투명·마스크 경계, 캐릭터 가장자리 잉크(일러스트 파이프라인)
- 폰트: 캡처에서 실제 글꼴이 의도한 글꼴(Pretendard 또는 대체 글꼴)인지, 글자가 깨지지 않았는지 (대체 폰트 렌더 사고 방지)
- 폰 크기 판독: 코드 영상은 `render.mjs page.html phone --phone 2`(폭 360px, 한 장에 8~12프레임). 이 크기에서 안 읽히는 글자는 폰에서도 안 읽힌다
- 빠른 동작: `render.mjs page.html strip --strip <초>`(연속 12프레임). 컨택트시트가 건너뛰는 튐·한 프레임 겹침·깜빡임을 본다

```bash
d=$(ffprobe -v error -show_entries format=duration -of csv=p=0 final.mp4)
for p in 0 0.25 0.5 0.75 0.98; do
  t=$(echo "$d*$p" | bc -l)
  ffmpeg -v error -y -ss "$t" -i final.mp4 -frames:v 1 -vf scale=960:-1 "07_qc/frame_${p}.jpg"
done
```

## C. 컷 경계 검사

모든 편집점 ±0.5초 필름스트립 + 파형 (`edit-manual.md` 5단계). 단어·받침 잘림, 팝, 큰 점프, 리액션-발언 불일치.

## D. 청취·내용 검사

- 대사 명료도: 작은 볼륨·폰 스피커 가정에서 BGM이 말을 덮지 않는가
- 자막 교정: 고유명사·숫자·부정어·띄어쓰기
- 제목·썸네일 약속이 첫 30초(쇼츠는 첫 2초)에 실현되는가
- 발언 의미가 편집으로 바뀌지 않았는가
- 권리: `assets.json`의 모든 음원·폰트·스톡에 라이선스 기록이 있는가

## 보고 형식

1. 결론 한 줄 (PASS / FAIL 항목 수)
2. 산출물 절대 경로
3. A 표 (측정값 그대로)
4. B·C 캡처 이미지 경로와 발견 사항
5. 요청 → 결과 → 수정 → 수정 결과 (수정이 있었다면 원문 그대로)
6. 확인하지 못한 것 (청취 등 사람이 해야 할 것 명시)

## E. 디렉터 채점 루프 (생성 영상, 전체 렌더 전)

기술 검사를 통과해도 "깔끔한 템플릿" 수준일 수 있다. 전체 렌더 전에 이 루프를 돈다. 잘 나온 사례들은 한 번에 나오지 않았다(163회 호출·약 7시간 사례도 있음).

1. 컨택트시트(`--sheet .5`), 폰 시트(`--phone 2`), 가장 빠른 구간 스트립(`--strip`)을 만들고 직접 연다.
2. 가혹한 모션 디렉터로서 채점한다. 만든 사람 입장에서 보지 않는다. 항목마다 1~10점:
   | 항목 | 8점 기준 |
   |---|---|
   | 훅 | 첫 2초 안에 가장 강한 그림이 있다 |
   | 폰 판독 | 360px 폭에서 모든 글자를 읽을 수 있다 |
   | 모션 품질 | 스프링으로 정착하고, 미끄러지듯 등속으로 움직이는 것과 죽은 프레임이 없다 |
   | 변화 | 2~4초마다 화면에 새 일이 일어난다 |
   | 구도 | 디자인 시스템(격자·고정 텍스트 위치)을 지키고 빈 공간이 의도적이다 |
   | 브랜드 정확도 | 실제 로고·색·UI이고, 지어낸 화면이나 수치가 없다 |
   | 사운드 싱크 | `sync-check` 통과, 컷과 타격이 맞는다(못 들었으면 "미청취"로 적고 점수 없음) |
   | 에너지 | 광고·소개·쇼릴은 다이내믹: `scripts/edit/energy.sh film.mp4` ENERGY PASS(10초당 컷 3.5 이상, 움직임 4.5 이상, 정지 프레임 30% 이하, 가장 긴 정지 0.5초 이하, 끝 카드 정지 1.0초 이하). 강의·튜토리얼·설명은 `--mode calm` |
3. 가장 큰 문제 3개를 타임코드와 함께 적는다. 특히 찾을 것: 교체 중 텍스트 겹침, 이징 없이 미끄러지는 요소, 가운데 제목+그라디언트 배경, 전부 페이드인, 흐린 확대 텍스트, 아무 일도 없는 박, 루프 이음매 끊김, 장르가 요구하지 않는데 들어간 모서리 라벨·프레임 테두리(쇼릴의 HUD처럼 레퍼런스 문법이면 허용).
4. 고치고, 바뀐 구간만 `--stills`나 `--strip`으로 다시 확인한 뒤 새 점수를 매긴다.
5. 모든 항목이 8점 이상이고 ENERGY PASS가 될 때까지 반복한다(최소 2라운드). 가독성을 고치려고 붙잡아 두는 시간을 늘리지 않는다: 글자를 키우거나 움직이는 채로 읽히게 한다(실측 교훈: 폰 판독만 고치다 정지 구간이 늘어 "이전 것보다 밋밋하다"는 평가를 받았다). 3라운드 이상 8점 미만인 항목이 있으면 규칙을 더 넣지 말고 `reference-breakdown.md`·`motion-references.md`로 돌아가 레퍼런스를 바꾼다.
6. 라운드마다 `work/review_log.md`에 점수·문제 3개·수정 내용을 남긴다. 보고서에는 첫 라운드와 마지막 라운드의 점수표를 같이 싣는다.
