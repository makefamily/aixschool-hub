# 릴스 스타일 고르기 + 편집 계획

촬영본 하나와 받아쓴 자막으로 편집 스타일을 고르고, 구간별 편집 계획표를 만든다. 스타일이 정해지면 해당 스킬의 화면 규칙으로 최종 영상을 만든다. 메모지형 4K 릴스는 `reel-reference-edit`, 여러 촬영 클립을 이어 붙이는 브이로그는 `vlog-reference-edit`, 인물 낭독 숏폼은 `ai-school-video-edit`을 쓴다.

## 공통 준비 (이 스킬과 릴스 편집 스킬들이 모두 따른다)
AI가 확인하고, 없는 것은 "무엇이 없어서 무엇을 깔겠다"고 말한 뒤 학생이 허락하면 설치한다. 학생에게 터미널 명령은 보여 주지 않는다.

| 필요한 것 | 맥 | 윈도우 |
|---|---|---|
| 파이썬 3, ffmpeg(ffprobe 포함) | 필요 | 필요 |
| 받아쓰기(자막 만들기) | 애플 칩 맥: mlx-whisper. 인텔 맥: faster-whisper | faster-whisper |
| 코드로 만드는 영상(메모지형·브이로그형) | Node 22 이상, HyperFrames, 크롬 | 같음(엣지도 가능) |
| 한국어 글꼴 | Pretendard(무료 OFL)가 있으면 먼저, 없으면 맥은 Apple SD Gothic Neo, 윈도우는 Malgun Gothic | |

- 설치 순서, 맥·윈도우 차이, HyperFrames를 작업 폴더 안에서만 쓰는 방법(전역 설치 금지, AI 스킬 자동 설치 끄기)은 `video-studio/references/code-video-setup.md`와 `video-studio/SKILL.md`를 따른다.
- 받아쓰기 결과는 완벽하지 않다. 학생에게 자막 문구를 한 번 확인받는다.
- 촬영본의 얼굴·목소리·남의 음악·남의 영상 소재는 학생 소유이거나 이용 허락을 받은 것만 쓴다. 외부 게시와 업로드는 이 스킬의 범위가 아니다.

## 스타일 고르는 기준
학생이 스타일을 말하면 그대로 쓴다. 말하지 않았으면(`auto`):
- 도구 이름·AI 서비스·대시보드·기능 시연이 반복되면 `reels-tool-demo`
- 숫자·주장·사례·감정 전개가 많으면 `reels-claim-numbers`
- 관점·에세이·이야기·개념 설명이 중심이면 `reels-info-visual`
애매하면 "화면으로 보여 줄 수 있나 -> 숫자·사례가 많은가 -> 이야기·개념이 중심인가" 순서로 다시 판단하고, 고른 이유를 한 줄로 학생에게 알린다.

## 실행 (AI가 한다)
1. 받아쓴 자막 JSON을 준비한다(`start`, `end`, `text` 칸의 목록).
2. `scripts/router.py`로 스타일 추천과 기본 `edit-plan.json` 초안을 만든다. 이 초안은 단어 수 세기 수준의 추정이다. 반드시 자막을 읽고 구간마다 화면 종류와 자료를 직접 고쳐 쓴다.
3. 미리보기가 필요하면 `scripts/render.py`로 만든다. 자막만 입힌 초안 영상이다(음성은 다시 자르지 않고 그대로 복사한다). 기본 2160x3840 30fps, 빠른 확인은 1080x1920으로 낮춘다. 글꼴은 맥·윈도우에 맞게 자동으로 고른다.
4. 선택한 스타일 스킬의 화면 규칙을 적용해 최종 영상을 만들고, 아래 점검표로 확인한다.

## 80점 점검표
최종 영상을 5개 항목 각 20점으로 평가한다: 화면 변화 리듬, 화면 역할 비율, 자막/글자, 자료 선택, 전환/끝 호출. 80점 미만이면 가장 낮은 항목부터 고쳐 다시 렌더한다(최대 3번). 점수는 대표 화면과 전체 재생을 직접 본 기록과 함께 적는다. 기계 점수만으로 통과를 선언하지 않는다. 직접 듣고 보지 않은 것은 "확인 못 함"으로 적는다.
