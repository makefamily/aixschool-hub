# UI 레퍼런스 선택·변형·추적 플레이북

이 문서는 고객 대면 랜딩페이지, 제품 데모, 새 시각 방향, 레퍼런스 기반 리디자인에서 사용한다. 단순 색상·간격·상태 수정처럼 참고자료 선택이 필요 없는 작업에는 로드하지 않는다.

목표는 특정 스타일을 표준으로 고정하는 것이 아니다. 좋은 출처에서 원리를 찾고, 프로젝트의 사용자·브랜드·콘텐츠·기술 조건에 맞게 변형하며, 무엇을 참고했는지 추적 가능하게 남기는 것이다.

## 우선순위

1. 프로젝트의 기존 디자인 시스템, 컴포넌트, 브랜드 가이드.
2. 사용자가 지정한 페이지·스크린샷·오픈소스.
3. 같은 사용자 과업을 해결하는 실제 제품 사례.
4. 다른 업종에서 전환 가능한 구조·상호작용 원리.
5. 아래 소스 카탈로그.

상위 근거가 충분하면 하위 소스를 억지로 추가하지 않는다. 보통 1~3개 출처면 충분하다.

## 선택 절차

### 1. 작업 신호를 적는다

```text
사용자 과업:
사업 목표:
화면 종류와 핵심 상태:
기존 브랜드·시스템 근거:
이번에 해결할 시각·상호작용 질문:
참고하지 않을 범위:
```

질문이 “예쁘게”처럼 넓으면 바로 소스를 늘리지 않는다. 정보 위계, 신뢰, 전환, 처리 상태, 모션, 이미지 방향처럼 검증 가능한 질문으로 바꾼다.

### 2. 출처마다 역할을 하나만 준다

예:

- Lazyweb: 가격표에서 비교 순서를 어떻게 보여주는가.
- Motion: 단계 완료 후 다음 결과가 등장하는 전환을 어떻게 구현하는가.
- 공냥 킷: 히어로에서 필요한 한 장의 시각 자산을 어떻게 명세하는가.

한 출처를 화면 전체의 정답으로 삼지 않는다.

### 3. 원리를 추출한다

```text
출처와 확인 시점:
관찰한 사용자 문제:
가져올 구조·행동 원리:
가져오지 않을 브랜드·장식 요소:
우리 프로젝트에 필요한 변형:
성공을 확인할 화면·행동:
```

색·그림자·반경·폰트 크기 같은 값은 기존 시스템이나 브랜드 근거가 없으면 최종값으로 고정하지 않고 `provisional`로 둔다.

### 4. 방향을 비교한다

고객 대면 신규 디자인은 `application-checklist.md`의 방향 3안 게이트를 따른다. 세 방향은 단순 색상 차이가 아니라 정보 위계, 레이아웃, 이미지 역할, 상호작용의 해석이 달라야 한다.

### 5. 실제 매체에서 검증한다

- 대표 콘텐츠와 긴·짧은·누락 콘텐츠.
- 작은 화면부터 넓은 화면까지의 의미 단위 줄바꿈.
- keyboard, focus, contrast, reduced motion.
- 로딩·오류·빈 상태와 재실행.
- 이미지·모션·필터가 초기 로드와 스크롤 성능에 미치는 영향.
- 정직 라벨: 재생 데모, 익명화·재구성, 예시 데이터 등.

Atomic Design의 component와 page/scenario 두 수준에서 모두 확인한다.

## 최종 보고

레퍼런스를 사용한 material UI 작업에는 다음을 짧게 남긴다.

```text
참고 출처:
출처에서 가져온 원리:
프로젝트에 맞게 변형한 부분:
의도적으로 복제하지 않은 부분:
실제 화면에서 확인한 결과:
```

작은 수정이거나 외부 레퍼런스를 사용하지 않았다면 이 블록을 생략한다.

## 금지

- 한 번 잘 나온 다크 AI 랜딩의 수치와 장식을 전역 기본값으로 고정하지 않는다.
- 레퍼런스를 브랜드 근거 없이 베끼거나, 스크린샷 좌표를 그대로 하드코딩하지 않는다.
- 출처 수를 품질의 대리 지표로 삼지 않는다.
- 접근성·성능·한국어 타이포그래피를 스타일 취향으로 취급하지 않는다.
- 라이선스를 확인하지 않은 코드·이미지·폰트·상표 자산을 복사하지 않는다.
- 내부 자료나 고객 데이터를 외부 레퍼런스 서비스에 업로드하지 않는다.
