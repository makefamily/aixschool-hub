# 롱폼 → 쇼츠 (구간 고르기 + 헤드카피 + 검수 화면)

## 하는 일
긴 영상 하나에서 따로 떼어도 이해되는 구간을 고르고, 위에 헤드카피 2줄, 가운데 원본, 아래 자막이 있는 세로 영상(1080x1920)으로 만든다. 군더더기 말("음", "어")과 늘어진 빈 구간은 잘라 낸다. 결과는 구간마다 mp4 한 개.

## 시작하기 전에 알려 줄 것 (권리와 한계)
- 내 영상이거나, 쓰도록 허락받은 영상만 쓴다. 남의 영상을 잘라 올리는 일은 도와주지 않는다. 다른 채널 영상이면 허락받았는지 먼저 묻는다.
- 원본 영상이 가로(16:9)일 때 가장 잘 맞는다. 세로 원본은 지원하지 않는다.
- 받아쓰기는 완벽하지 않다. 검수 화면에서 구간과 문구를 확인하는 것이 이 스킬의 핵심이다.

## 필요한 것 (AI가 확인하고, 없으면 설치해도 되는지 학생에게 물은 뒤 설치)
| 필요한 것 | 맥 | 윈도우 |
|---|---|---|
| 파이썬 3.10 이상, ffmpeg | 있어야 함 | 있어야 함 |
| 영상 받기(yt-dlp), 숫자 계산(numpy) | 파이썬 패키지로 설치 | 같음 |
| 음성 받아쓰기 | 애플 칩 맥은 mlx-whisper | faster-whisper(인텔 맥도 이쪽). 처음에 모델을 내려받느라 시간이 걸린다 |
| 얼굴·박힌 자막 찾기(확대 배치, 원본 자막 읽기) | 맥에서만 된다(맥 기본 기능 사용) | 지원 안 함. 이 기능은 끄고 원본 비율 그대로 만든다 |
| 업로드(선택) | 연결 필요 | 연결 필요 |
- 설치 순서와 명령은 AI가 알아서 실행한다. 학생에게는 "무엇이 없어서 무엇을 깔겠다" 정도만 말하고 허락을 받는다. 터미널 명령을 학생에게 보여 주지 않는다.
- 패키지는 학생의 작업 폴더 안 가상환경에만 설치한다. 전역 설치와 사용자 설정 폴더 변경은 하지 않는다.
- 글꼴 Pretendard(무료 OFL)는 이 폴더에 들어 있다. 라이선스 파일도 같이 있다.

## 순서 (AI가 실행)
1. 링크와 목적을 받는다. 내 영상인지 확인하고, 만들 개수(기본 최대 10개)와 하단에 넣을 내 채널 이름을 묻는다.
2. `lfs.py run <링크>`: 영상을 받고 받아쓰기까지 한 뒤 `ai/plan-request.md`를 만들고 멈춘다(종료 코드 3).
3. **AI(너)가 구간을 고른다.** `ai/plan-request.md`를 읽고 JSON만 담은 `ai/plan-response.json`을 같은 폴더에 쓴다. 규칙은 요청 파일 안에 있다. 문장 번호는 요청 파일에 있는 번호만 쓴다. 헤드카피는 영상에 실제로 나온 말에서만 만들고 없는 사실·숫자를 지어내지 않는다.
4. `lfs.py plan <영상ID>`: 응답을 반영하고 검수 화면을 연다. 학생이 구간을 쓸지 말지 고르고, 헤드카피 2줄과 하단 문구, 자막 위치, 색 모양(시안·흰+파랑·노랑)을 고친 뒤 "선택한 것 렌더"를 누른다.
   - 카피를 다시 뽑고 싶다고 하면 `lfs.py recopy <영상ID>`로 요청 파일을 만들고, 3번처럼 `ai/recopy-response.json`을 쓴다. 이어서 `lfs.py review <영상ID>`.
5. 렌더가 끝나면 `shorts-work/<영상ID>/out/cNN.mp4`를 학생에게 알리고, 첫 구간 시작·중간·끝을 직접 확인해서 자막이 잘리거나 말이 끊긴 곳이 있는지 보고한다. 확인하지 못한 것은 못 했다고 쓴다.
6. 업로드는 학생이 원할 때만. 아래 "올리기" 참고.

## 막혔을 때
- 받아쓰기 도구가 없다는 메시지: 위 표대로 설치하도록 학생에게 허락을 구한다.
- 영상 받기 실패: 링크가 공개 영상인지, 비공개·연령 제한이 아닌지 확인한다. 다운로드 도구 업데이트로 풀리는 경우가 많다. 그래도 안 되면 학생이 영상 파일을 직접 작업 폴더에 `source.mp4`로 넣고 이어 간다.
- 자막이 이상하게 나가는 영상(소리 작음, 사투리, 겹치는 말): 검수 화면에서 문구를 직접 고치게 한다.
- 윈도우에서 글꼴이 다르게 나오면 동봉한 Pretendard가 읽히는지 확인한다.

## 올리기 (선택, 학생 확인 필수)
두 길이 있다. 학생에게 고르게 한다.
1. 직접 올리기: 만든 mp4를 유튜브 스튜디오에서 학생이 올린다. 가장 안전하다. 원하면 `aside-browser` 스킬로 스튜디오 화면을 열어 업로드 칸까지 같이 간다(공개 버튼은 학생이 누른다).
2. 연결로 올리기: **허브 설정 › 연결 › 유튜브**에 클라이언트 ID와 비밀번호를 넣어 둔 경우에만 가능하다. 값이 비어 있으면 AI가 구글 클라우드에서 만드는 순서를 화면으로 안내하고, 학생이 채운다. 처음 올릴 때 브라우저에서 학생이 직접 허락한다. `yt_upload.py`는 제목·설명을 보여 주는 확인 단계를 먼저 거치고, 학생이 "올려"라고 해야 **비공개**로 올린다. 공개 예약은 학생이 시각을 정했을 때만 건다. 하루 한도에 걸리면 다시 시도하지 않고 멈춘다.
- 어느 쪽이든 자동으로 공개하지 않는다. 제목·설명은 `youtube-channel-manager` 스킬로 다듬을 수 있다.

## 지킬 것
- 학생 계정·채널·키 값을 파일이나 대화에 그대로 적지 않는다. 연결 값은 허브가 넣어 주는 환경 변수로만 쓴다.
- 구간과 헤드카피가 영상 내용을 부풀리지 않게 한다("1500만원 굳었다" 같은 숫자는 영상 안에 있을 때만).
- 하단 문구에 원본 채널(출처)을 적는다. 허락받은 영상이면 허락받았다는 사실을 학생이 직접 확인한 것으로 기록한다.
- 작업 파일은 현재 작업 폴더의 `shorts-work/`에만 만든다. 스킬 폴더는 고치지 않는다.

## 파일 설명 (AI용)
`lfs.py` 진입점·검수 서버, `lfs_core.py` 다운로드·받아쓰기·컷·자막·렌더, `review.html` 검수 화면, `yt_upload.py` 연결 업로드, `tools/*.swift` 맥 전용(얼굴·글자 찾기), `fonts/` Pretendard.
