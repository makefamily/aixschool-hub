# 강의 덱 만들기

필요한 프로그램: python(맥에서는 `python3`, 아래 명령의 `python`을 `python3`로 바꿔 쓴다), 크롬 같은 웹 브라우저. 덱 검사에서 화면 확인(`--render`)을 하려면 Playwright가 필요하다. 없으면 사용자에게 설치가 필요하다고 알린다.

강의·특강·세미나에서 쓰는 덱은 PDF 장표가 아니라 **키보드로 넘기는 라이브 프레젠터 HTML**이다. 덱과 프롬프터가 한 세트다.

## 덱 스타일 v1 · v2

| | 스타일 v1 | 스타일 v2 |
|---|---|---|
| 틀 | `templates/style-v1/` | `templates/style-v2/` |
| 뿌리 | 검증된 수업·차시 강의 덱 | 검증된 전환형 웨비나 덱 |
| 모양 | 아이보리·기본 강조색(파랑, df.css 의 --accent), 얇은 구성, 박스 금지, 캡처 풀화면 장 | 아주 굵은 글자, 바탕 세 가지(흰·어두운색·브랜드색) 번갈아, 색 칸(카드)·아이콘, 장 유형 31가지 |
| 잘 맞는 것 | 수업·차시 강의, 설명 중심 | 무료 강의 → 유료 전환 웨비나, 설득 중심(투표·질문답·혜택·가격·자주 묻는 질문) |
| 색 | 고정 | 덱마다 `META["theme"]`로 바꾼다. 구조·레이아웃·구성·글꼴·흐름만 가져오고 색과 내용은 바꾼다 |

### 두 스타일 공통으로 추가된 장 (실제 특강 덱에서 검증)

| 무엇 | v2 (`templates/style-v2`) | v1 (`templates/style-v1`) | 언제 |
|---|---|---|---|
| 빨간 박스 → 확대 (1-A) | 아무 장에 `box=[(x,y,w,h)]` + 확대 장 `zoomed=True`. `slides.py` 의 `BOXED()` 로 두 장 한 번에 | `shot` 에 `box=` + `k="zoom"`. `*BOXED()` | 캡처 글씨가 화면에서 원본의 70% 미만(레티나 2배는 CSS 크기로 환산). lint [3-17] WARN. 확인 목록 3-17 |
| 따라하기 화면 꽉 차게 | `k="screen"` | `k="screen"` | 덱 흐름에 맞춰 가이드 페이지 화면을 그대로. 가이드에 가로 화면 미디어쿼리 + 960×540·2배 캡처. 짧은 주소는 큰 글자 한 장. 확인 목록 8-10 |
| 시중 서비스 한 장 | `k="market"` | `k="market"` | '이런 것도 만들 수 있다' 블록. 가격은 공식 페이지 확인값만. 확인 목록 10-8 |
| 달력 | `k="cal"` | `k="cal"` | 과정 일정(오늘·수업·사이 기간). 확인 목록 3-13 |
| 투표 보기 4~6개 | `poll` 이 자동으로 2~3줄 격자 | (v1에 투표 없음) | 화면 밖으로 밀리던 버그 수정 |

캡처를 넣을 땐 뒤 창·옆 창에 개인 대화·이름이 비치지 않는지 확대해서 본다(확인 목록 3-18, 실제 사고 있었음). 지시받은 장을 미루면 보고에 장 번호와 이유를 적는다(10-9).

v2 첫 실물 예시는 딥네이비 #020425 · 노랑 #FFCF0D 조합이다. 다크·주황 `assets/deck.css`는 옛 방식이라 쓰지 않는다. 어느 스타일이든 단계마다 실제 캡처·영상, 누를 때 진행, 글자만 있는 덱 금지. 프롬프터는 파트별 발화량이 배정 시간×320자의 65~85%를 채워야 완료.

## 덱 확인 목록 (매번 대조)

덱·프롬프터·따라하기·덱 영상을 만들며 받은 수정 지시 80여 개를 [references/deck-checklist.md](references/deck-checklist.md)에 모았다. 이 스킬의 다른 내용보다 그 목록이 우선한다.

- **착수할 때:** 목록 1·2장을 읽는다. 설계서 맨 위에 목적 한 줄, 새로 짜기/고치기 구분, 레퍼런스 출처, 찾아본 기존 자료(단톡방·팀원 자료·가진 이미지) 경로를 적는다.
- **고칠 때:** 대화 중간의 수정 지시도 목록에 대조한다. 지적받은 표현은 덱 전체에서 같은 것을 찾아 고치고, 목록 맨 아래 '지적 낱말 목록'에 추가한다. 새 원칙이면 해당 장에 날짜와 원문 한 줄을 붙여 추가한다.
- **완료 보고 전:** 덱 폴더에서 `python -m http.server 8765 --bind 127.0.0.1`을 띄우고(브라우저 주소는 http 와 로컬 주소, 포트 8765) `python scripts/deck_lint.py deck.html [프롬프터.html] --render <그 로컬 주소>/deck.html`(이 스킬 폴더 기준 경로)가 FAIL 0이어야 한다(`--render`가 줄바꿈을 실제로 잰다). 나머지 수동 항목은 눈으로 대조한다. 보고에 '확인 목록 N개 중 통과 / 미통과·이유'와 받은 지시 원문 대조표(10-2)를 넣는다. 미통과가 있으면 완료라고 하지 않는다.
- 가장 자주 어긴 것: 일상어(16회) · 글자만 있는 장(12) · 레퍼런스 먼저 분해(11) · 실제 환경 끝까지 QA(11) · 덱 목적 고정(7) · 지시 반영 대조(7).

## 순서를 지킨다

덱을 바로 쓰지 않는다. 아래 순서를 건너뛰면 다시 만들게 된다.

1. **구조 설계서** (`슬라이드구조설계.md`) — 장수·유형 배분·시간대·설계 원칙
2. 사용자 확인
3. **덱** (`deck.html`) — `assets/`의 deck.css·deck.js를 인라인
4. **프롬프터** (`script.html`) — 덱 확정 후

강의 자료는 강사가 사람 앞에서 말로 재현해야 한다. 설계서를 먼저 보여주고 흐름에 동의를 받은 뒤에 덱을 쓴다.

## 구조 설계서에 반드시 넣을 것

`templates/구조설계서.md`를 복사해 채운다. 빠지면 안 되는 것:

- **유형별 장수와 비중** — A 임팩트 문장 / B 개념 대비 / C 실제 화면·시연 표지판 / D 프로세스 / 챕터
- **시간대별 슬라이드 배분** — 몇 분에 몇 번 슬라이드인지
- **설계 원칙** — 왜 이 비중인지를 문장으로. 예: "라이브 시연을 안 하므로 캡처가 시연을 대신한다. 한 장짜리 스크린샷은 증거고, 서너 장 연속은 시연이다"
- **아직 없는 것** — 찍어야 할 캡처, 받아야 할 자료
- **12블록 누락 점검** — 아래 기준으로 각 역할의 실제 반영 위치·상태·필요한 최소 보완을 기록한다

라이브 시연을 하면 C 비중이 낮고 A가 높다. 시연을 안 하면 C를 절반까지 올리고 캡처를 시퀀스로 푼다.

## 12블록으로 누락 점검

구조 설계서를 검토할 때 공유 정본 [12블록 점검 기준](references/12-block-gap-check.md)을 읽고 기존 대본·장표·영상·시연·실습에 매핑한다. 최종 QA에서는 실제 저장된 산출물과 대조해 같은 표를 갱신한다.

12개는 강의 역할을 확인하는 기준이다. 순서·장수·시간 비율을 강제하지 않으며, 결과 먼저 보기와 짧은 설명→시연→실습의 반복을 유지할 수 있다. 이미 반영된 역할을 중복 추가하지 말고, 강의별 제약 안에서 빠진 부분만 최소 보완한다. 승인된 기존 자료는 요청된 범위 밖에서 수정하지 않는다.

## 덱 마크업 규칙

`assets/deck.css` 첫 줄에 박혀 있는 규칙이다. 어기지 않는다.

- **박스·카드·패널 금지.** 테두리 친 상자에 내용을 담지 않는다 (스타일 v1과 옛 방식 규칙. 스타일 v2는 색 칸을 쓴다)
- **타이포 3단**만 쓴다 — `--d`(디스플레이) `--l`(리드) `--m`(마이크로)
- **씬당 액센트 한 곳.** `.acc`를 한 슬라이드에 두 번 쓰지 않는다
- **성공색(`--seal`)은 마지막 봉인 1회**
- **모션은 발표자가 누를 때만.** 상시 애니메이션 금지

쓸 수 있는 것:

```html
<section>
  <div class="kicker">상단 작은 라벨</div>
  <h1>큰 문장<br>줄바꿈은 직접 통제</h1>
  <p class="lead">
    <span class="s">한 줄</span>
    <span class="s"><span class="acc">액센트는 여기 한 곳만</span></span>
  </p>
</section>

<section class="chapter"><div class="kicker">1부</div><h1>부 제목</h1></section>

<section>
  <ul>
    <li>항목<small>보조 설명</small></li>
  </ul>
</section>

<section>
  <ol class="q"><li>오늘의 지도 항목</li></ol>
  <p class="note">각주</p>
</section>
```

## 문장 쓰는 법

강사 본인의 말투로 쓴다. 짧은 단문, 존댓말, 과장 없음.

- 한 장에 한 메시지. 설명을 장표가 다 해버리면 시연이 복습이 된다
- 질문을 던지는 장표를 쓴다 — "진짜 되는가", "어디까지 되는가"
- 결과를 먼저 보여주고 시작한다. 설명부터 하면 초반에 이탈한다
- 숫자는 실측값만. 추정치면 추정이라고 쓴다
- 이모지 금지. "마법" 금지

## 라이브 시연이 있을 때

시연 앞뒤에 표지판 슬라이드를 둔다. 화면을 옮겨 다니면 "지금 어디인지"를 잃는다.

```html
<section class="demo">
  <div class="kicker">지금부터 볼 것</div>
  <h1>무엇을 보는지</h1>
  <div class="hold">화면을 넘기겠습니다. 어떻게 보시면 되는지 한 줄.</div>
</section>
```

돌아와서는 "방금 본 것"을 한 문장으로 못박는다. 이 두 장 사이는 나중에 녹화본으로 바꿔 끼워도 흐름이 유지된다.

AI 작업 대기가 긴 시연은 **실행을 먼저 걸어두고** 도는 동안 설명 슬라이드를 진행한 뒤 결과를 확인하는 배치로 짠다.

## 만드는 방법

`assets/deck.css`와 `deck.js`를 읽어 `<style>`·`<script>`에 인라인하고, 슬라이드를 파이썬으로 조립해 `deck.html` 하나로 떨어뜨린다. 파일 하나면 어디서든 열린다.

```
<div id="bar"></div>
<div id="stage"> ...섹션들... </div>
<div id="hud"><span id="cur">1</span> / <span id="tot">0</span></div>
```

`deck.js`가 `cur`·`tot`·`bar`를 참조하므로 이 세 요소는 빠뜨리지 않는다. 좌우 화살표·스페이스·클릭으로 넘어가고 해시에 현재 장이 남는다.

## 검증

만들고 끝내지 않는다. 브라우저로 실제로 넘겨본다.

브라우저는 이 작업 전용 창(또는 전용 세션)으로 연다. 다른 작업이 쓰는 브라우저를 닫거나 넘기지 않는다. 덱 폴더에서 로컬 서버(`python -m http.server 8765`)를 띄운 뒤 `deck.html`을 열고 개발자 도구 콘솔에서 아래를 실행한다.

```js
JSON.stringify({슬라이드:document.querySelectorAll('section').length, 총:document.getElementById('tot').textContent, 깨진이미지:Array.from(document.querySelectorAll('img')).filter(i=>i.naturalWidth===0).length})
go(11)   // 11번째 장으로 이동해 화면을 확인
```

슬라이드 수가 맞는지, 이미지가 깨지지 않았는지, 대표 슬라이드 몇 장이 의도대로 보이는지 확인한다.

## 프롬퍼터

덱이 확정된 뒤에 만든다. `assets/script.css`를 쓴다. 들어갈 것:

- 상단 타이머 바 — 시작·리셋·덱 새 창·글자 크기
- **덱과 프롬프터는 양방향으로 연결한다.** (`templates/style-v1/deck.js` · `templates/style-v2/deck.js`에 기본 포함) 덱을 넘기면 프롬프터가 그 장으로 따라가 표시되고, 프롬프터의 'PPT N번'을 누르면 덱이 그 장으로 간다(postMessage + BroadcastChannel 'aix-deck'). 덱 틀을 복사해 올 때 이 연결이 빠지지 않았는지 두 창을 띄워 실제로 확인한다(덱 틀을 새로 복사하다 이 연결이 빠졌던 사고가 있었다). file:// 로 연 페이지끼리는 연결이 안 된다 — 수업 땐 덱 폴더에서 `python -m http.server 8765 --bind 127.0.0.1` 을 띄우고 같은 주소의 script.html 과 deck.html 을 연다(또는 https 발행본). 기준 코드: 두 `deck.js` 의 '프롬프터 연동' 블록
- **파트 바로가기(목차)는 기본으로 숨긴다.** 타이머 바에 '목차' 토글 버튼을 두고, 누르면 펼치고 목차 항목을 누르면 다시 접는다. 상태는 브라우저에 기억한다(목차 버튼이 화면을 너무 차지하기 때문). 붙여 쓸 코드: `assets/prompter-toc-toggle.html`
- **대본 덩어리마다 `data-n="장 번호" data-s="단계(0부터)"`를 붙인다.** 덱에서 한 번 누를 때(장 넘김·스텝) 대본 한 덩어리(`.press` 방식). `deck_lint.py deck.html 프롬프터.html`이 덱 스텝 수와 대본 덩어리 수를 대조한다
- 섹션마다 시각(`data-start`)과 제목
- **흰 글씨 = 말할 내용.** 그대로 읽을 문장은 표시해 둔다
- **지금 손으로 할 것**은 따로 구분한다
- 시작 전 준비물 체크리스트 — 열어 둘 것, 닫을 것
- 실패했을 때 대응

대본량이 부족하면 강사가 현장에서 막힌다. 장표마다 액션과 멘트를 세세하게 쓴다.

## 참고할 실물

강의 성격에 맞는 실물 예시는 사용자가 가진 이전 덱(특강 덱, 영상 내장형 덱, 라이브 시연형 덱, 수업 차시 덱)에서 고른다. 가진 것이 없으면 `templates/style-v1`·`templates/style-v2`를 기본 틀로 쓴다.

자기 덱만 참고하지 않는다. 잘된 외부 레퍼런스(강의 영상·세일즈 라이브·다른 강사 PPT)를 장면 단위로 먼저 분해한다(확인 목록 2-1).

영상 내장형은 흰 배경에 영상을 박아 넣은 변형이다. 스타일은 강의 성격에 맞춰 정하되 위 마크업 규칙은 공통이다.
