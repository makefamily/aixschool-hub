# 카드뉴스 만들기 (SNS 콘텐츠 디자이너)

주제나 글 하나를 받아 카드뉴스 이미지 파일까지 만든다. 글자는 AI 그림이 아니라 화면 글자로 얹기 때문에 오타와 깨짐이 없다. 올리기는 하지 않는다. 사람이 한다.

## 학생에게 하는 말 규칙
- 터미널 명령어, 파일 경로 문법, 코드를 학생에게 보여주지 않는다. 필요한 실행은 AI가 직접 하고, 결과만 쉬운 말로 알린다.
- 대화에는 기획표와 결과 요약만 짧게. 긴 내용은 파일로 저장한다.

## 흐름 한눈에
0 내 자료 읽기 → 1 기획표 → 2 디자인·장 수·규칙 정하기 → 3 원고 쓰기(deck.json 또는 cards.json) → 4 이미지 준비 → 5 표지 먼저 → 6 전체 만들기와 검사 → 7 모아보기·ZIP

## 쓰는 파일
- 작업 폴더 결과물: `기획.md`, `규칙.md`(기본 틀일 때), `cards/01.png`부터, `모아보기.png`(전체 한눈에), `카드뉴스.zip`, `index.html`(기본 틀 미리보기), `caption.txt`(올릴 글, 있을 때)
- 내부 파일: `deck.json`(템플릿 3종 원고+그림 계획) 또는 `cards.json`(기본 틀 원고), `brand.json`, `images/`(표지·배경 그림), `cards/src/`(카드 한 장씩의 원본)
- 이미 카드뉴스 결과물이 있는 작업 폴더면 새 하위 폴더를 만들어 거기에 쓴다. 이전 것을 덮지 않는다.
- 스킬 폴더: `scripts/`(make_cards.py 기본 틀, make_deck.py 템플릿 3종, gen_images.py 이미지, pack.py 모아보기·ZIP), `templates/`, `references/design-rules.md`(기본 틀 규칙), `references/deck-spec.md`(템플릿 3종 원고 규칙), `assets/fonts/`(글꼴)

## 0. 내 자료부터 읽기
1. 허브 폴더의 `my/about.md`(누구이고 누구에게 파는지)와 `my/writing/`(내 글 몇 편)을 읽는다. 말투, 독자, 자주 쓰는 단어를 카드 문장에 반영한다. 내 글 문장을 통째로 베끼지 않는다.
2. `my/`에 색·글꼴·브랜드 이름·SNS 이름이 있으면 읽어 둔다.
3. `my/`가 없거나 비어 있으면 그대로 진행하고, 마지막에 한 줄만 말한다: "내 소개와 글을 `my/`에 채워 두시면 다음 카드뉴스가 내 말투에 더 가까워집니다."
4. 주제나 원고가 안 정해졌으면 먼저 묻는다. 원고에 없는 숫자, 후기, 성과, 수강생·고객 이야기는 쓰지 않는다.

## 1. 기획표 (이미지부터 만들지 않는다)
맨 위에 "이 카드뉴스를 누구에게 보여줄지" 한 줄을 적고 `기획.md`로 저장한다. 장 수는 5장 또는 10장 중 학생이 고른다(말이 없으면 10장을 제안).

| 장 | 역할 | 큰 제목 | 화면(그림) |
|---|---|---|---|
| 1 | 표지 훅 | | |
| 2~ | 문제 → 방법(순서) → 결과 | | |
| 마지막 | 다음 행동 하나 | | |

- 5장: 표지, 문제, 방법, 결과, 다음 행동. 10장: 표지 1 + 본문 8(문제 1~2, 원인 1, 방법 3~4, 결과·주의 2) + 마감 1.
- 큰 제목은 두 줄로 끊는다. 화면 칸에는 무엇이 보일지 적는다(대화, 전/후 비교, 번호 흐름, 체크리스트, 설정 화면, 파일 내용 등).
- 여기서 멈추고 표만 보여 준다. 학생이 확인하기 전에는 이미지를 만들지 않는다. "한 번에 다 만들어 줘"라고 미리 말했으면 표를 보여 주고 바로 이어 간다.

## 2. 디자인·규칙 정하기
학생에게 한 번에 묻는다(이미 말한 것은 묻지 않는다):
1. 디자인: **기본 틀**(아이보리·어두운 패널, 이미지 없이 가볍게) / **포스터**(강한 색 바탕, 초대형 노랑 제목, 배경 사진 필요) / **에디토리얼**(밝고 깔끔한 예시 카드, 표지 그림 1장) / **그런지**(위 화면 + 아래 검정 굵은 글씨, 그림 불필요). 같은 주제를 여러 디자인으로 올리지 않는 편이 좋다고 한 줄 덧붙인다. 비교해 보고 싶으면 폴더를 나눠 둘 다 만들 수 있다.
2. 내 브랜드 색이 있으면 알려 달라(없으면 템플릿 기본 색). 우선순위: `my/`의 브랜드 정보 → 학생 답 → 기본값.
3. SNS 이름(handle)이 있으면.
- 기본 틀 규칙은 `references/design-rules.md`, 템플릿 3종 원고 규칙은 `references/deck-spec.md`를 읽는다.
- 정한 값으로 `brand.json`을 저장한다(키: handle, bg, ink, panel, onpanel, accent, font; 템플릿 3종은 handle과 accent만 쓴다). 템플릿 3종은 기본이 템플릿 고유 색이고, 학생이 브랜드 색을 원할 때만 그 색을 대표색 자리에 넣는다.

## 3. 원고 쓰기 (학생 AI가 대화 안에서 직접)
- 기본 틀: `cards.json`(형식은 `templates/cards.example.json`). 카드 종류 cover, point, steps, compare, closing.
- 템플릿 3종: `deck.json`(형식은 `templates/deck.example.json`, 글자 수 한도와 그림 종류는 `references/deck-spec.md`). 글과 함께 장마다 보여 줄 그림(대화·비교·체크리스트 등)과 표지·배경 장면 설명까지 같이 쓴다.
- 학생 말투와 자료를 반영하고, 자료에 없는 숫자·후기·성과는 쓰지 않는다. 글이 길면 형식 검사가 돌려보내니 줄인다.
- 원고만 먼저 검사해 볼 수 있다(AI가 실행: `python <이 스킬 폴더>/scripts/make_deck.py --dir <작업 폴더> --template 08-poster --check-only`. 윈도우에서 `python`이 안 되면 `py`).

## 4. 이미지 준비 (템플릿 포스터·에디토리얼만, 선택)
포스터는 이미지 4개(표지 1 + 배경 3), 에디토리얼은 표지 1개. 기본 틀과 그런지는 이 단계가 없다. 방법은 세 가지이고 학생이 고른다.

**A. AI 그림 (구독 한도를 쓴다)**: Codex가 설치돼 로그인돼 있을 때만.
1. 먼저 알리고 허락받는다: "AI 그림을 만들면 본인 ChatGPT(Codex) 사용 한도가 줄어듭니다. 표지 한 장만 만들까요, 4장 다 만들까요?" 허락 없이 만들지 않는다. 한 장 만드는 데 30초 안팎이 걸렸다. 실패해도 자동으로 다시 시도하지 않고 이유만 알린 뒤 B나 C로 넘어갈지 묻는다.
2. 필요한 그림과 설명을 먼저 확인한다(돈 안 든다): `python <스킬 폴더>/scripts/gen_images.py --dir <작업 폴더> --template <템플릿> --list`
3. 허락 뒤 만든다: `... gen_images.py --dir <작업 폴더> --template <템플릿> --run` (표지만이면 `--only cover`). 모델 이름은 정하지 않는다. 학생 Codex의 기본 설정을 그대로 쓴다.
4. 지금 Codex로 일하고 있으면 `--run` 대신 `images/prompts.json`의 설명으로 Codex 내장 이미지 기능을 직접 써서 `images/`에 `cover.png`, `bg1.png`… 이름으로 저장해도 된다.
5. Codex가 없거나 로그인이 안 됐으면 A는 건너뛰고 B·C만 안내한다.
6. 만든 그림은 반드시 직접 열어 본다. 글자·로고·사람 얼굴이 있으면 그 그림은 쓰지 않고(`images/`에서 빼고) 학생에게 다시 만들지 묻는다. 얼굴·로고·상표를 그리게 하는 설명은 쓰지 않는다.

**B. 내 사진 폴더**: 학생이 가진 사진 폴더를 받아 순서대로 표지·배경에 복사한다(`... gen_images.py --dir <작업 폴더> --template <템플릿> --from-folder <사진 폴더>`). 사진 속 다른 사람 얼굴은 허락 없이 쓰지 않는다고 한 줄 알린다.

**C. 이미지 없이**: 그대로 진행한다. 포스터는 색 배경, 에디토리얼은 어두운 배경으로 나온다. 기본 틀·그런지는 늘 이 방식이다.

## 5. 표지 한 장 먼저
- 기본 틀: `python <스킬 폴더>/scripts/make_cards.py --dir <작업 폴더> --cover-only`
- 템플릿 3종: `python <스킬 폴더>/scripts/make_deck.py --dir <작업 폴더> --template <템플릿> --only 1 --no-pack` (브랜드 색을 쓰면 `--brand-color` 추가)
- 만들어진 `cards/01.png`를 직접 열어 글자 깨짐, 잘림, 줄바꿈, 강조 위치를 확인한다. 스크립트의 `OK`만 믿지 않는다. 표지를 보여 주고 "이 느낌으로 나머지를 만들까요?"를 묻는다. 고칠 말이 나오면 원고나 `brand.json`을 고쳐 다시 만든다.

## 6. 전체 만들기와 검사
- 기본 틀: `... make_cards.py --dir <작업 폴더>`
- 템플릿 3종: `... make_deck.py --dir <작업 폴더> --template <템플릿>`
- 줄마다 `OK`이고 크기가 `1080x1350`이어야 한다. 검사 항목은 글자가 상자나 안전 여백을 넘침, 글자끼리 겹침, 이미지·글꼴이 안 열림이다.
- **검사에 탈락한 장(FAIL)** 은 출력에 장 번호와 이유(어느 글이 넘치거나 겹쳤는지)가 나온다. 그 장의 제목·설명을 줄이거나 그림(kind)을 바꿔 `--only 3,5`처럼 그 장만 다시 만든다. 이 확인이 끝나기 전에는 "완료"라고 하지 않는다. 2번 고쳐도 탈락하면 그 장은 더 단순한 그림 종류로 바꾼다.
- 몇 장은 직접 열어 본다(표지 + 글이 가장 많은 장 + 마지막 장).

## 7. 모아보기와 ZIP
전체가 통과하면 스크립트가 자동으로 `모아보기.png`(카드 전부를 한 장에, 5열 격자)와 `카드뉴스.zip`(카드 PNG 전부 + 올릴 글)을 작업 폴더에 만든다. `모아보기.png`를 직접 열어 깨진 장이 없는지, 장 순서와 색 흐름이 어색하지 않은지 확인한다.

## 하지 말 것
- 성과, 숫자, 후기, 수강생·고객 이야기를 지어내지 않는다. 사람 얼굴, 로고, 상표, 실제 서비스 화면을 그리지 않는다(그림 설명에도 넣지 않는다).
- 학생이 정하지 않은 장 수·구조를 바꾸지 않는다. 고칠 때는 그 장만 고친다.
- 올리기, 예약, 메시지 발송은 하지 않는다. 브라우저 프로그램 이름으로 전체 종료 명령을 내리지 않는다(학생이 열어 둔 브라우저가 닫힌다).
- AI 그림은 허락 없이, 자동 재시도로 만들지 않는다. 비밀번호·키를 파일에 적지 않는다.

## 윈도우에서
- 같은 스크립트가 윈도우 Chrome 또는 Edge를 찾아 쓴다. 둘 다 없으면 멈추고 "Chrome이나 Edge가 필요합니다"만 알린다. `python`이 안 되면 `py`로 실행하고, 둘 다 없으면 Python이 필요하다고 한 줄로 알린다.
- 템플릿 3종은 스킬에 들어 있는 글꼴(Pretendard, Black Han Sans)을 쓰므로 맥과 거의 같게 나온다. 기본 틀은 Pretendard가 없으면 맑은 고딕으로 대신 나온다(`brand.json`의 `font`로 바꿀 수 있다). 터미널 그림 속 글꼴만 맥은 Menlo, 윈도우는 대체 고정폭 글꼴이라 조금 다르다.
- Codex 이미지 만들기는 윈도우 Codex에서 로그인돼 있어야 한다. 윈도우에서 실제로 돌려 본 결과는 아직 없다(확인 전).

## 다 하면
"카드뉴스 N장을 `cards` 폴더에 저장했습니다(크기 1080x1350 확인). 한눈에 보는 `모아보기.png`와 묶음 `카드뉴스.zip`도 만들었어요."를 말하고, 질문 하나: "고칠 장이 있나요? 번호만 말씀해 주세요."
끝에 한 줄: "사용한 스킬: cardnews-maker". `my/`가 비어 있었으면 0단계의 한 줄도 덧붙인다.
