# 숏폼 영상편집자 — shorts-cutter

## 하는 일
자막을 이야기 단위로 묶어 훅 말 점수와 길이 범위로 후보를 고르고, 겹치는 후보는 뺀 뒤 후보표·숏폼 자막·후보 화면을 만든다.
결과는 AI가 느낌으로 매기는 것이 아니라 스크립트가 표(규칙)대로 세고 판정한다. 기준을 바꾸고 싶으면 스크립트가 아니라 규칙 표를 고친다.

## 필요한 것
- 필요한 프로그램: Python 3 (없으면 멈추고 무엇이 없는지 한 줄로 알린다), ffmpeg(영상까지 자를 때만)
- 키·로그인: 없음. 이 스킬은 아무 서비스에도 접속하지 않고 파일만 읽고 쓴다.

## 작업 폴더
- 작업 폴더는 지금 작업 폴더 안의 `숏폼-후보` 로 한다. 처음 실행하면 연습 자료와 규칙 표가 그 안에 한 번만 복사된다. 이미 있는 파일은 덮어쓰지 않는다.
- 스킬 폴더의 `samples` 는 원본이다. 고치지 않는다. 사용자가 고치는 것은 작업 폴더의 복사본이다.

## 순서
1. 먼저 한 가지를 묻는다: "연습 자료로 먼저 한 번 볼까요, 바로 내 자료로 할까요?" 연습 결과를 사용자의 실제 결과처럼 말하지 않는다.
2. 내 자료로 할 때: 자막은 `01_자막` 에 두거나 `--srt <자막파일>` 로 알려 준다. 자막이 없으면 먼저 받아쓰기로 만든다(video-studio).
   내 자료의 칸 이름이 다르면 사용자에게 어느 칸이 무엇인지 한 번 확인하고, 원본은 고치지 않고 칸 이름을 맞춘 사본을 쓴다.
3. 규칙 표를 내 것으로 바꾼다. 무엇으로 바꿀지 모르면 사용자에게 묻는다(지어내지 않는다).
   - `02_규칙/훅말.csv` (훅 말, 점수, 이유): 내 손님이 멈춰서 보는 말
   - `02_규칙/숏폼길이.csv` (항목, 값, 설명): 최소·최대 길이
   - `02_규칙/빼는구간.csv` (빼는 말, 이유): 인사·잡담 등 숏폼에서 뺄 말
4. 이 스킬 폴더의 `scripts/run.py` 를 Python 으로 실행한다. 작업 폴더는 `--work <작업 폴더 경로>` 로 넘긴다 (선택 옵션: 영상까지 자르기: `--render <영상파일>`(ffmpeg 필요, 사용자 허락 뒤에만, 원본 그대로)). 이 줄은 AI용이다. 사용자에게 명령어를 보여 주지 않는다.
5. 결과를 열어 본다. 만들어지는 것: 결과/숏폼후보.html, 결과/숏폼후보.csv, 결과/숏폼_N.srt, (자를 때) 세로 영상 파일. HTML 화면은 허브 오른쪽 미리보기에 띄운다.
6. 스크립트가 알려 주는 확인 3가지를 읽고 그대로 전한다.
   - 숏폼 길이가 정해둔 범위 안인가
   - 후보끼리 겹치지 않나
   - 첫 3초 안에 훅 말이 있나
   "확인 필요"가 있으면 이유를 쉬운 말로 알리고, 규칙 표를 어떻게 고치면 되는지 제안한 뒤 다시 돌린다. 표를 고치기 전에 사용자에게 먼저 묻는다.
7. 사람 눈으로 한 번 더 볼 것을 사용자에게 알린다(`references/검수표.md` 참고).
   - 후보 구간을 직접 틀어 보니 앞뒤가 어색하게 잘리지 않나

## 지킬 것
- 원본 영상은 고치거나 덮어쓰지 않는다. 자르기 전에 후보 구간을 사용자에게 보여 주고 확인받는다.
- 스크립트 코드는 고치지 않는다. 결과가 이상하면 규칙 표나 입력 자료를 본다.
- 사용자에게 보이는 안내와 만든 화면·문서에 터미널 명령어와 내 컴퓨터 폴더 경로를 넣지 않는다.
- 키·비밀번호·토큰을 묻거나 저장하지 않는다.

## 하지 않는 것
- 영상을 올리지 않는다.

## 다 하면
결과 화면을 연 뒤 한 줄로 알린다: "OO를 만들었어요. 확인 3가지 중 N가지 통과, 확인 필요 M개." 그리고 질문 하나: "규칙 표에서 바꾸고 싶은 기준이 있나요?"
어떤 스킬을 썼는지(`shorts-cutter`) 결과 끝에 한 줄로 남긴다.
