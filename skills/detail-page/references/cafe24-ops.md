# 카페24 업로드 & 운영

## 1. 이미지 규격

| 용도 | 규격 | 비고 |
|---|---|---|
| 상세설명 | 폭 1080px, 세로 자유 | 1만px 넘으면 조각내서 올린다 (조각당 1200~1500px) |
| 대표(썸네일) | 1000×1000 | 목록·검색 노출용. 가격 숫자를 박으면 인상 때 같이 갈아야 함 |
| 조각 파일 | JPG q88, 폭 800~1080 | PNG는 용량이 3~5배. 사진 없는 벡터풍이면 PNG도 무방 |

## 2. 업로드 순서

1. `render_detail.py` 로 전체 PNG 생성 → 눈으로 검수
2. `slice_detail.py` 로 조각내기
3. 카페24 관리자 → 상품 → 상품수정 → **상세설명** → 에디터에서 이미지 순서대로 삽입
4. 대표이미지에 썸네일 1000×1000 업로드
5. 모바일 미리보기로 한 번 더 확인 (글자 크기가 제일 자주 터진다)

## 3. 디지털 상품 자동 수령 (주문완료 페이지)

파일: 주문완료 자동수령 스크립트(`cafe24_order_result_delivery.html`, 이 문서의 절차대로 직접 작성)

- 붙이는 곳: 디자인(스마트디자인) → `order/order_result.html`, 주문완료 안내문구 아래
- 동작: 주문완료 페이지의 **상품명 텍스트 + `product_no`** 를 읽어서
  `DELIVERY` 배열에 등록된 상품일 때만 다운로드 박스를 띄운다
- 상품 추가는 배열에 한 줄 추가하면 끝:
  ```js
  { match:["강사의 모집 시스템"], no:[278], title:"...", desc:"...", btn:"받기", url:"https://..." }
  ```
- 문자 자동발송(센드맨)과 **같은 링크**를 쓰고, 박스에 "문자로도 보냈어요 · 스팸함 확인" 문구를 남긴다

## 3-1. 관리자 화면 자동화로 되는 것 / 안 되는 것 (실측)

API 상품 권한(`mall.write_product`)이 없으면 관리자 UI를 브라우저 자동화로 몰아야 하는데,
되는 것과 안 되는 것이 명확히 갈린다.

| 작업 | 가능? | 방법 |
|---|---|---|
| 상품명·가격·판매/진열 상태 | ✅ | 필드명 직접 세팅. 가격은 `product_price[1]`(기본몰)·`product_price[4]`, 소비자가는 `product_custom[1]` |
| 상세설명 이미지 업로드 | ✅ | 에디터 툴바 **이미지 삽입** → 드롭존 `input[type=file]`에 업로드. 업로드 경로는 `/web/upload/NNEditor/YYYYMMDD/<원본파일명>` |
| 상세설명 HTML 주입 | ✅ | `product_description_IFRAME`의 `body.innerHTML` **과** `textarea[name=product_description]` 둘 다 세팅. iframe이 소스라 textarea만 바꾸면 제출 시 덮인다 |
| **대표이미지(썸네일)** | ✅ | **(26-07-29 갱신)** hidden `input#imageFiles` 에 파일을 직접 실어주면 된다. Claude-in-Chrome `file_upload` 툴로 ref를 지정해 업로드 → `change` 이벤트 디스패치 → 상세/목록/작은목록/축소 4종이 한 번에 채워진다. **"+ 등록" 버튼은 절대 클릭하지 말 것**(OS 파일 다이얼로그가 열려 세션이 막힌다). URL등록 레이어(`#layerImageUrl`)는 여전히 미리보기만 바꾸고 서버로 안 간다 |

함정:
- **드롭존은 한 번에 1장만** 올라간다. 여러 개 넘기면 첫 장만 처리됨. 툴바에 **다중 이미지 삽입** 버튼이 따로 있음.
- **업로드 성공 여부는 눈으로 믿지 말고 HEAD로 찍어라.** 업로드 경로가 `/web/upload/NNEditor/YYYYMMDD/<원본파일명>` 으로 예측 가능하니
  `fetch(url,{method:'HEAD'})` 로 12장을 한 번에 검증한다. 툴은 "업로드했다"고 하는데 서버엔 없는 경우가 실제로 나온다(패널이 닫힌 채 실려서).
- **에디터에 들어간 순서는 신경 쓰지 마라.** 파일을 전부 올려 URL만 확보한 뒤,
  `product_description_IFRAME` 의 `body.innerHTML` 과 `textarea[name=product_description]`(+`_mobile`)에
  **정렬된 `<img>` HTML을 통째로 덮어쓰는 게 훨씬 안정적이다.** 삽입 위치·커서 문제를 통째로 우회한다.
- **저장 클릭 후 탭이 5초 넘게 멈춘다**(이미지가 많을수록). 스크린샷이 타임아웃 나도 실패가 아니다 —
  `tabs_context` 로 URL이 `/exec/admin/.../productregister` → `/disp/admin/.../productmanage` 로 넘어갔는지 보고,
  검증은 **외부 HTTP 요청으로 실제 상품페이지**를 받아 문자열 검사한다.
- 업로드 전 **패널이 열려 있는지 스크린샷으로 확인**할 것. 툴바 버튼은 토글이라 클릭이 패널을 닫아버리면 업로드가 조용히 실패한다.
- **4,000px 넘는 이미지를 에디터에 넣으면 렌더러가 얼어붙는다**(스크립트 주입 타임아웃). → HTML 주입과 저장 버튼 클릭을 **한 번의 JS 호출**로 묶어라. 검증은 얼어붙은 탭 대신 **다른 탭/외부 HTTP 요청**으로.
- 이미지 교체 시 **파일명을 바꿔라**(dc0 → dcB0). 같은 이름이면 캐시 때문에 확인이 안 된다.
- 검증은 관리자 화면 말고 **실제 상품 페이지 HTML을 받아서** 문자열 검사하는 게 확실하다.

## 3-2. 0원 신청 상품(웨비나·리드마그넷) 등록 세팅

무료 웨비나·전자책은 **0원 상품 주문 = 신청서**로 쓴다. 주문자 정보가 곧 DB.

- **배송비는 반드시 무료로.** 배송방법을 **`자체배송`** 으로 고르면 배송비가 무료가 된다.
  안 그러면 0원 상품인데 결제창에서 배송비가 붙어 신청이 막힌다 (유저 실측)
- **진열상태·판매상태는 둘 다 `전체`** 체크. 몰이 여러 개(한국어/영어/일본어)면 전부 켜는 게 기본
- 판매가는 기본몰에 `0` 입력 후 **`환율 자동계산`** 클릭 → 나머지 몰(USD·JPY)까지 0으로 채워진다.
  이 버튼을 안 누르면 다른 몰 가격이 비어 저장이 막힌다
- 등록 후 `.env` 의 `CAFE24_PRODUCT_NO` 에 새 번호를 **쉼표로 추가**(`275,279`)해야
  매시간 도는 auto_ship 이 이 주문도 자동 배송완료 처리한다. 안 하면 배송준비중으로 쌓인다
- 신청자 안내(라이브 링크 등)는 상품별 문자·메일 자동 발송으로 걸어둔다

## 4. 가격을 올릴 땐 반드시 3곳 세트로

가격은 세 군데에 박혀 있다. 하나만 바꾸면 "이미지엔 33,000, 결제는 44,000"이 되어 클레임 소지.

1. **카페24 판매가** — 상품 → 상품목록 → 상품코드 클릭 → 판매정보 탭 → 판매가 → 저장
2. **상세페이지 이미지** — `detail_premium.html` 의 가격 3곳(히어로 / rise 밴드 / CTA) 수정 → 재렌더 → 교체
3. **썸네일 이미지** — `thumbnail_premium.html` 수정 → 재렌더 → 대표이미지 교체

운영이 번거로우면: **히어로에서 큰 가격 숫자를 빼고** "현재가는 결제창에서 확인 · 판매량 늘수록 인상"만
남긴다. 이미지가 고정돼서 카페24 판매가만 바꾸면 끝난다. (임팩트 ↓, 운영 ↑)

인상은 되돌리지 않는 것이 원칙 — 내렸다 올리면 희소성이 죽는다.
자세한 단계표는 프로젝트의 `가격_인상_운영가이드.md` 참고.
